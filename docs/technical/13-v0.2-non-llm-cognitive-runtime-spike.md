# v0.2 Codex Starter Pack — Non-LLM Cognitive Runtime Spike

## Purpose

This starter pack is meant to give Codex enough context to work on the next phase without drifting into product-polish mode or accidentally adding an LLM.

The v0.1 prototype proved one bounded predictive loop:

```text
manual input
→ prediction
→ signal
→ interpretation
→ evidence quality
→ belief/no-update
→ action/no-action
→ safety
→ outcome
→ memory
→ loop record
```

v0.2 should be a rapid experimental spike. The goal is to test whether the runtime can replace many jobs normally handled by an LLM using non-LLM methods: rules, embeddings, retrieval, Bayesian-style scoring, schemas, graph records, and deterministic uncertainty gates.

## v0.2 Goal

Test whether the core “mind” loop can become more capable without using an LLM.

This version should explore whether the system can:

- run from a CLI
    
- persist loop records
    
- retrieve relevant memory without LLMs
    
- classify/interpret input using non-LLM methods
    
- score uncertainty and evidence explicitly
    
- perform belief update/no-update using scored evidence
    
- create abstention / “I don’t know” decisions through deterministic gates
    
- represent causal or graph-like relationships between records
    
- validate records with schemas
    
- produce readable loop reports
    

This is allowed to be rough. It is a spike, not a polished product release.

---

## What LLMs Would Normally Do

A normal LLM-based agent would often be used for:

1. Understanding user input
    
2. Interpreting vague language
    
3. Deciding what the input is about
    
4. Retrieving relevant memory
    
5. Summarising prior context
    
6. Estimating confidence
    
7. Suggesting belief updates
    
8. Suggesting actions
    
9. Explaining decisions in human language
    
10. Saying “I don’t know”
    

v0.2 asks whether those jobs can be approximated without an LLM.

## Non-LLM Substitution Map

|LLM Job|Non-LLM Replacement Candidates|v0.2 Recommendation|
|---|---|---|
|Input understanding|keyword rules, regex, scikit-learn text features, embeddings|Start with rules + embeddings|
|Interpretation|template matching, taxonomy matching, semantic similarity|Use interpretation templates + embeddings|
|Ambiguity handling|score thresholds, multiple candidate interpretations, conflict flags|Add uncertainty/abstention gate|
|Memory retrieval|JSONL search, keyword search, embeddings, vector store|Start with local embedding index or Chroma|
|Summarisation|deterministic templates, record summaries, extractive summaries|Use simple record-based reports|
|Confidence estimation|source reliability, similarity score, Bayesian-style scoring|Add custom score model first|
|Belief updates|scoped target taxonomy, update thresholds, Bayesian-style posterior|Implement lightweight scored belief update|
|Action suggestions|action registry, decision tables, expected-effect rules|Use deterministic action policy|
|Explanation|record chain reports, JSON summaries, graph reports|Produce readable loop report|
|“I don’t know”|abstention thresholds, low evidence gates, conflict detection|Make abstention first-class|

## Proposed v0.2 Capabilities

### 1. CLI runner

Run one loop from PowerShell:

```powershell
python -m bpm_runtime.main run-once "The current section is too vague."
```

Optional flags later:

```powershell
--json
--summary
--save
--trace-dir traces/
```

### 2. JSONL persistence

Persist records into:

```text
traces/events.jsonl
traces/loops.jsonl
traces/memory.jsonl
```

### 3. Config-driven runtime

Move these into config files where practical:

```text
config/boundary.json
config/action_registry.json
config/uncertainty_policy.json
config/evidence_policy.json
```

### 4. Uncertainty and abstention

Add records/concepts such as:

```text
UncertaintyGateRecord
AbstentionRecord
ClarificationRequestRecord
ConflictRecord
```

The system should be able to return:

```text
I do not have enough evidence to update belief or act.
```

without relying on an LLM.

### 5. Embedding-based memory retrieval

Explore:

```text
sentence-transformers
Chroma or simple local JSON index
```

Create records such as:

```text
MemoryRetrievalRecord
SimilarityMatchRecord
RetrievedContextRecord
```

### 6. Bayesian-style evidence/belief scoring

Do not start with heavy probabilistic programming unless needed.

Start with a transparent custom score:

```text
prior_confidence
source_reliability
semantic_similarity
interpretation_confidence
conflict_penalty
posterior_confidence
update_threshold
```

### 7. Causal/record graph

Represent cause/effect between records:

```text
low_evidence -> no_update
no_update -> no_action
safe_action -> outcome
outcome -> memory_trace
```

Start with graph-like records before adopting a heavy graph library.

### 8. Schema validation

Add lightweight JSON Schema validation for record dictionaries.

### 9. Readable loop reports

Generate a human-readable report:

```text
What happened?
What was predicted?
What signal arrived?
What did the system infer?
What evidence was strong/weak?
Did it update belief?
Did it act or abstain?
What uncertainty remains?
```

## Stage-by-Stage v0.2 Runtime Design

### Manual input

Current: wraps manual text into `SignalRecord`.

v0.2 additions:

- classify input type
    
- detect command vs observation vs feedback
    
- mark ambiguous input
    
- prevent input from becoming direct command authority
    

### Prediction

Current: generic `PredictionRecord`.

v0.2 additions:

- generate prediction templates from prior belief
    
- include expected signal type and likely belief target
    
- include confidence and uncertainty
    
- do not copy incoming manual text
    

### Signal

Current: stores manual text payload.

v0.2 additions:

- source reliability
    
- sensor/source type
    
- admissibility checks
    
- payload summary
    

### Interpretation

Current: deterministic interpretation.

v0.2 additions:

- interpretation candidates
    
- semantic similarity to known templates
    
- confidence score
    
- ambiguity/conflict detection
    

### Evidence quality

Current: categorical high/medium/low/inconclusive.

v0.2 additions:

- numerical score
    
- reason components
    
- source reliability
    
- semantic similarity
    
- conflict penalty
    
- abstention threshold
    

### Belief/no-update

Current: high/medium updates, low/inconclusive no-update.

v0.2 additions:

- prior confidence
    
- posterior confidence
    
- target-specific updates
    
- scoped belief updates only
    
- no-update and abstention as first-class results
    

### Action/no-action

Current: action candidate or no-action.

v0.2 additions:

- expected effect scoring
    
- risk scoring
    
- uncertainty reduction estimate
    
- action registry from config
    
- no-action if uncertainty too high
    

### Safety

Current: boundary/path/viability checks.

v0.2 additions:

- config-driven policy
    
- capability admission
    
- deterministic abstention gates
    
- property-based safety tests
    

### Outcome

Current: outcome record.

v0.2 additions:

- expected vs observed effect comparison
    
- success/failure classification
    
- outcome uncertainty
    

### Memory

Current: memory trace references upstream records.

v0.2 additions:

- embedding index
    
- memory retrieval records
    
- similar prior loop retrieval
    
- record-based memory reports
    

### Loop record

Current: ordered linked record chain.

v0.2 additions:

- graph representation
    
- replay support
    
- report generation
    
- persistence references

## Success Criteria

v0.2 is successful if it can demonstrate most of the following without an LLM:

- run one loop from CLI
    
- save loop records to JSONL
    
- retrieve similar memory or context using embeddings
    
- classify or interpret basic input using non-LLM methods
    
- produce low-confidence / abstention results
    
- say “I don’t know” via explicit uncertainty rules
    
- use scored evidence rather than only labels
    
- apply scoped belief update/no-update
    
- generate action/no-action from deterministic policy
    
- keep safety deterministic
    
- generate readable loop report
    
- preserve 100+ existing tests and add new tests
    

---

## Failure Criteria

v0.2 reveals a problem if:

- basic interpretation is useless without an LLM
    
- embeddings return noisy/unhelpful memory matches
    
- Bayesian-style scoring is fake or uninformative
    
- abstention blocks nearly everything
    
- safety policy becomes unmanageable
    
- the runtime becomes hard to inspect
    
- too many dependencies are added without clear value
    
- the loop starts acting before evidence/safety gates
    
- the system cannot explain why it updated or abstained
    

---

## Boundaries

Do not add:

- LLM integration
    
- web access
    
- autonomous external actions
    
- broad shell/tool automation
    
- real document editing
    
- UI
    
- cloud deployment
    

Do not modify:

- `Source Documents/`
    
- existing technical docs unless intentionally creating v0.2 planning docs
    

Keep:

- `main` stable
    
- v0.2 work on spike branch
    
- frequent tests
    
- inspectable records

3. Add persistence flags and JSONL saving
    
4. Add readable loop report
    
5. Add uncertainty/abstention records and gates
    
6. Add config-driven action/evidence/uncertainty policies
    
7. Add simple embedding memory index
    
8. Add memory retrieval records
    
9. Add scored evidence model
    
10. Add scored belief update/no-update
    
11. Add graph/causal record representation
    
12. Add schema validation
    
13. Add Hypothesis/property-based tests for safety invariants
    
14. Review what worked and decide whether v0.3 should add LLM proposal adapters or continue non-LLM work
