## **1. Where it strongly aligns**

Predictive coding theories generally propose that the brain maintains internal models that predict incoming sensory input, compares those predictions with actual sensory signals, and uses prediction error to update the model. Rao and Ballard's classic visual-cortex model describes higher-level predictions being compared with lower-level input, with residual error carried forward as the signal that updates the system. 

Your system maps very closely onto that conceptual structure:
    
    
    Predictive brain theory:
    internal model → prediction → sensory input → prediction error → model update
    
    Your system:
    belief state → prediction frame → signal envelope → interpreted observation → prediction error → precision-weighted belief update

So conceptually, the architecture is very close to the predictive-processing family.

## **2. Where it aligns with active inference**

Your system is also close to **active inference**, especially in how it treats action.

Predictive processing by itself often focuses on perception: prediction, sensory input, and error. Active inference extends this by saying organisms can reduce prediction error not only by changing beliefs, but also by acting to change future sensory input. Friston's free-energy / active-inference work is often summarized this way: a system can update its model or act to make expected sensory states more likely. 

Your A08 document, "Action as Future Error Management," is highly aligned with that.

You are not treating action as:
    
    
    obedience
    tool use
    goal execution

You are treating action as:
    
    
    a bounded intervention expected to change future signal, uncertainty, error, viability, or model quality

That is very active-inference-like.

The key difference is that your system makes this operational and safety-governed. You do not just say "act to reduce prediction error." You require:
    
    
    action candidate
    expected effect
    cost
    risk
    permission
    capability admission
    viability check

    memory trace

So your system is not simply "active inference." It is more like:

a safety-governed, engineering-oriented active-predictive runtime.
