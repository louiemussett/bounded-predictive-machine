# v1 — Adaptive

## 1. What this version IS (conceptually)
A trace-conditioned adaptive machine that can turn repeated transitions into explicit regularity records.

## 2. What it DOES (in practice)
- **Commands available:** all v0 commands plus `adapt`, `regularities`.
- **Observable behavior:** reads `traces/events.jsonl`; writes `adaptive/regularities.json`; quarantines invalid/unregistered trace records in `quarantine/rejected_records.jsonl`.
- **What changes over time:** support/contradiction counts, confidence/uncertainty labels, and processed trace ID set.

## 3. Internal capabilities added
- Trace validation against allowed trace types and registered interfaces.
- Transition derivation from `state_trace`/transition payloads.
- Regularity indexing by `(signal, previous, current)`.
- Confidence + uncertainty derivation from support/contradiction counts.

## 4. What changed from previous version
- **Added:** adaptive update pipeline (`run_adaptive_update`).
- **Became possible:** persistent learning of recurring transition structure from runtime traces.

## 5. Why these changes were necessary
The system needs compressed transition structure before it can form expectations or evaluate prediction mismatch.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime run --ticks 3`
  - `python -m phase0_runtime adapt`
  - `python -m phase0_runtime regularities`
- **Expected behavior:** new regularity records appear with counts/confidence and reference source trace IDs.

## 7. Limitations
- No expectation schema yet.
- No predictions or mismatch evaluation.
- No decision/action coupling to learned structure.

## 8. Conceptual interpretation
This is an **adaptive** system (regularity extraction), still not predictive or agent-like.

## 9. Transition to next version
What is missing: forward-looking structures derived from regularities.
Next version adds: expectation and prediction artifacts with evaluation outcomes.
