# v6 — Interfaces

## 1. What this version IS (conceptually)
A governed interface machine: boundary crossing is explicit, permissioned, traced, and fail-closed.

## 2. What it DOES (in practice)
- **Commands available:** all prior commands plus `read-external` (and `cycle --external`).
- **Observable behavior:** reads only from allowed external path subtree; rejects traversal; records interface access attempts with result and permission data.
- **What changes over time:** interface usage traces and external read outcomes (`success`, `empty`, `failure`).

## 3. Internal capabilities added
- Interface governance checks (registered interface + allowed operation).
- External read interface `iface_external_read` with path allowlist controls.
- Access-attempt trace payload (`interface_id`, `operation`, `result`, `permission_used`, `success`).

## 4. What changed from previous version
- **Added:** controlled boundary interaction with external input files.
- **Became possible:** limited world-facing sensing without violating runtime safety model.

## 5. Why these changes were necessary
A mature runtime needs bounded input channels; governance ensures external contact is inspectable and constrained.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime read-external --path sample.txt`
  - `python -m phase0_runtime traces --last 10`
- **Expected behavior:** file preview is returned when allowed, and access attempt is always traced.

## 7. Limitations
- Read-only external interaction.
- No arbitrary file writes outside runtime root.
- No network/API action channel.

## 8. Conceptual interpretation
This stage is **bounded adaptive interfacing**, still strongly non-open autonomy.

## 9. Transition to next version
What is missing: reusable bounded work units with lifecycle state.
Next version adds: constrained task system.
