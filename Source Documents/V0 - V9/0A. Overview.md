# System Versions Overview (v0 → v9)

## Purpose of the system
This repository implements a bounded machine runtime that can:
- sample and persist internal state,
- record traces of transitions,
- derive adaptive regularities,
- form and check predictions,
- perform constrained internal/external actions,
- execute bounded tasks,
- process structured human commands,
- and run integrity/recovery operations.

Its purpose is not open-ended autonomy; it is controlled, inspectable operation inside a strict runtime boundary.

## What kind of system this is
This is a **bounded runtime** and a **trace-based adaptive system**:
- **Bounded runtime:** all operations are constrained to a fixed root (`machine_cognition_runtime/`), explicit interfaces, and fail-closed checks.
- **Trace-based adaptive system:** learning and prediction are derived from persisted trace records (`traces/events.jsonl`) and stored adaptive artifacts (`adaptive/*.json`).

## What “autonomous” means here
In this architecture, “autonomous” means:
- **bounded:** only registered actions and governed interfaces are allowed,
- **traceable:** major operations are written to structured trace records,
- **non-open autonomy:** no unconstrained planning, no arbitrary tool/network execution, no uncontrolled world mutation.

So autonomy here is **operational self-management under constraints**, not unrestricted agency.

## Full version ladder
- **v0** — Foundation runtime
- **v1** — Adaptive regularity extraction
- **v2** — Predictive layer (expectations + predictions + mismatch checks)
- **v3** — Integrated cycle loop
- **v4** — Controlled change (bounded decision/action)
- **v5** — Viability-centered control
- **v6** — Governed external interfaces
- **v7** — Constrained task execution
- **v8** — Human-facing structured command interface
- **v9** — Mature integrated system (health, recovery, compaction, summary, limits)

## Key concepts
- **State:** current machine condition stored in runtime state files (for example `current_state.json`, `runtime_status.json`, `viability.json`).
- **Trace:** append-only event records (`events.jsonl`) describing observed state, operations, errors, and system events.
- **Transition:** a change between previous/current values (derived from state snapshots or explicit transition payloads).
- **Adaptive regularity:** a recurring transition pattern with support/contradiction counts and confidence.
- **Expectation:** a structured projection derived from adaptive regularities.
- **Prediction:** a pending expected transition tied to an expectation and state snapshot.
- **Mismatch:** prediction evaluation outcome when observed traces diverge from predicted transition.
- **Controlled action:** execution chosen only from a bounded allowlist (`heartbeat_write`, `no_op`, `read_external`) under policy.
- **Interface governance:** registry + permission checks + traced access attempts for interface operations.
- **Task:** a bounded execution record with explicit allowed actions, max steps, terminal conditions, and status.

## Layer-by-layer evolution
The system grows by adding one bounded capability class at a time:
1. **Operational substrate (v0):** state + traces + fail-closed runtime.
2. **Adaptation (v1):** regularities learned from traces.
3. **Prediction (v2):** regularities transformed into expectations/predictions and evaluated.
4. **Closed-loop operation (v3):** run predict→observe→adapt as an integrated cycle.
5. **Controlled intervention (v4):** choose and execute bounded actions.
6. **Viability logic (v5):** action policy anchored to viability score/state.
7. **Governed world contact (v6):** external read via registered, permissioned interface.
8. **Bounded tasking (v7):** reusable constrained execution units.
9. **Human operation layer (v8):** structured command queue/result channel.
10. **System maturity (v9):** integrity checks, recovery, compaction, and resource-limit enforcement.
