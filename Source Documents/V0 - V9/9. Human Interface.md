# v8 — Human Interface

## 1. What this version IS (conceptually)
A structured human-operation machine: humans interact via validated command records, not free-form chatbot behavior.

## 2. What it DOES (in practice)
- **Commands available:** all prior commands plus `process-commands` and `console`.
- **Observable behavior:** reads pending commands from `external_input/commands.jsonl`, executes mapped bounded operations, writes outcomes to `external_output/results.jsonl`, updates command status.
- **What changes over time:** command lifecycle (`pending` → `processed`/`rejected`) and result stream records.

## 3. Internal capabilities added
- Strict command schema validation.
- Supported command types: `create_task`, `run_cycle`, `run_task`, `inspect`, `read_traces`.
- Command tracing (`command_received`, `command_processed`, `command_rejected`).
- Optional local console parser that emits structured command records.

## 4. What changed from previous version
- **Added:** stable human-facing operational interface layer.
- **Became possible:** queue-based human supervision and repeatable command processing.

## 5. Why these changes were necessary
As system complexity grows, direct CLI-only operation is less manageable; structured command I/O improves auditability and operational control.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime process-commands`
  - `python -m phase0_runtime console`
- **Expected behavior:** pending command records are validated, executed when allowed, and mirrored to results with success/failure summaries.

## 7. Limitations
- Command set is fixed and bounded.
- No open natural-language agent layer.
- Rejected commands fail closed rather than improvising.

## 8. Conceptual interpretation
This is a **supervised bounded agent interface**, not a chatbot/autonomous planner.

## 9. Transition to next version
What is missing: integrated system integrity lifecycle (health diagnosis, recovery, compaction, and limit enforcement).
Next version adds: mature system operations.
