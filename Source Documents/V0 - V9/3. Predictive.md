# v2 — Predictive

## 1. What this version IS (conceptually)
An adaptive-predictive machine: it projects expected transitions and later checks observed traces for match/mismatch.

## 2. What it DOES (in practice)
- **Commands available:** all prior commands plus `expect`, `predict`, `check-predictions`.
- **Observable behavior:** writes `adaptive/expectations.json` and `adaptive/predictions.json`; updates prediction status (`matched`, `mismatched`, `inconclusive`) and mismatch records with cause attribution fields.
- **What changes over time:** pending predictions get resolved; mismatch statistics accumulate.

## 3. Internal capabilities added
- Expectation construction from confidence-qualified regularities.
- Prediction construction with state snapshots.
- Prediction evaluation against observed `state_trace` records.
- Mismatch records containing `cause_type` and `cause_confidence`.

## 4. What changed from previous version
- **Added:** explicit expectation and prediction schemas + evaluator.
- **Became possible:** operational forecasting and error/mismatch accounting.

## 5. Why these changes were necessary
Regularities describe past tendencies; prediction logic is required to make those tendencies actionable in future cycle control.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime adapt`
  - `python -m phase0_runtime expect`
  - `python -m phase0_runtime predict`
  - `python -m phase0_runtime check-predictions`
- **Expected behavior:** predictions are generated, then labeled matched/mismatched/inconclusive after evaluation.

## 7. Limitations
- No integrated recurring loop orchestration yet.
- No viability-based action policy.
- No governed external action usage.

## 8. Conceptual interpretation
This is **predictive** but still mostly analytic; limited action coupling.

## 9. Transition to next version
What is missing: automatic integration of prediction, observation, adaptation, and status update in one repeated control loop.
Next version adds: cycle orchestration.
