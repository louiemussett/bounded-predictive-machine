# v0 — Foundation

## 1. What this version IS (conceptually)
A bounded state-and-trace machine: it samples internal runtime state, records transitions, and fails closed on critical errors.

## 2. What it DOES (in practice)
- **Commands available:** `run-once`, `run`, `status`, `traces`, `reset-runtime`, `validate` (baseline checks).
- **Observable behavior:** writes `state/current_state.json`, `state/previous_state.json`, `state/runtime_status.json`; appends `state_trace`, `operation_trace`, `resource_trace`, `tick_summary`.
- **What changes over time:** tick count, sampled metrics, trace history, and runtime status.

## 3. Internal capabilities added
- Required runtime directory boundary.
- Interface registry loading and registration checks.
- Default-deny action boundary for internal operations.
- Structured trace writer with allowed trace types.
- Per-tick state diff generation.

## 4. What changed from previous version
- **Added:** executable bounded runtime substrate.
- **Became possible:** repeatable state sampling and persistent audit trail.

## 5. Why these changes were necessary
Without a bounded substrate and trace persistence, later adaptation/prediction layers would have no reliable operational base.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime reset-runtime`
  - `python -m phase0_runtime run --ticks 2`
  - `python -m phase0_runtime traces --last 5`
- **Expected behavior:** runtime writes state snapshots and multiple trace records per tick, then reports recent traces.

## 7. Limitations
- No adaptation or prediction.
- No controlled decision/action policy.
- No task model.
- No governed external interface use.

## 8. Conceptual interpretation
This is a **reactive bounded runtime**, not yet adaptive.

## 9. Transition to next version
What is missing: extraction of recurring transition patterns.
Next version adds: adaptive regularity formation from accumulated traces.
