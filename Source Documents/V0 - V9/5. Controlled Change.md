# v4 — Controlled Change

## 1. What this version IS (conceptually)
A bounded decision-and-action machine: it can choose from a strict action set and execute controlled state changes with traceability.

## 2. What it DOES (in practice)
- **Commands available:** all prior commands plus `act`, `heartbeat`, `plan`.
- **Observable behavior:** decision records include rationale/confidence; chosen action is executed (`heartbeat_write`, `no_op`, optionally `read_external` when enabled); post-action transition traces are emitted.
- **What changes over time:** heartbeat state, operation traces, and decision history.

## 3. Internal capabilities added
- Decision policy constrained to `_ALLOWED_ACTIONS`.
- Decision trace + execution trace + post-action observation trace.
- Non-executing internal `plan` output with bounded actions only.
- Causal attribution fields on operation/mismatch records.

## 4. What changed from previous version
- **Added:** explicit controlled action pathway.
- **Became possible:** limited intervention instead of pure observation/adaptation.

## 5. Why these changes were necessary
A runtime that only predicts but never acts cannot preserve or adjust operation; bounded action introduces practical control while keeping safety constraints.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime viability`
  - `python -m phase0_runtime plan`
  - `python -m phase0_runtime act`
- **Expected behavior:** viability is read, a bounded plan is printed, then one controlled action is chosen/executed and traced.

## 7. Limitations
- Action set is intentionally tiny.
- No unrestricted tool execution.
- No task-level orchestration yet.

## 8. Conceptual interpretation
This stage is **controlled agent-like behavior** (bounded actuation), not open-ended autonomy.

## 9. Transition to next version
What is missing: a first-class viability model that systematically anchors action urgency.
Next version adds: explicit viability scoring/state model.
