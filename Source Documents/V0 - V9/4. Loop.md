# v3 — Loop

## 1. What this version IS (conceptually)
A closed operational loop machine that repeatedly executes predict→tick→evaluate→adapt and records cycle-level outcomes.

## 2. What it DOES (in practice)
- **Commands available:** all prior commands plus `cycle`.
- **Observable behavior:** each cycle tick builds expectations/predictions, runs runtime tick, evaluates mismatches, updates adaptation/reliability, computes viability, and emits cycle traces.
- **What changes over time:** prediction stats, reliability score, runtime error-rate estimate, and cycle trace summaries.

## 3. Internal capabilities added
- Integrated cycle orchestration routine.
- Runtime status update using mismatch-derived error rate.
- Reliability score from adaptive confidence distribution.
- Cycle-level operation trace (`cycle tick completed`).

## 4. What changed from previous version
- **Added:** loop-level integration of previously separate commands.
- **Became possible:** deterministic recurring self-update process rather than manual stage execution.

## 5. Why these changes were necessary
Separate commands are useful for debugging, but operational systems need a stable recurring loop to preserve coherence across layers.

## 6. Example run
- **Commands:**
  - `python -m phase0_runtime cycle --ticks 3`
  - `python -m phase0_runtime status`
- **Expected behavior:** three integrated loop ticks run and status reflects accumulated cycle outputs.

## 7. Limitations
- Action layer is optional and still bounded/simple.
- External interface usage is not yet the central governed focus.
- Tasks/human command channel not yet available.

## 8. Conceptual interpretation
This is **agent-like loop structure** without open autonomy.

## 9. Transition to next version
What is missing: explicit controlled intervention logic (decision + bounded action execution).
Next version adds: controlled change mechanisms.
