# **A11 -- Machine Metacognition**

**Project status:** cognitive-core canon  
**Purpose:** define how the system monitors the quality, uncertainty, conflict, limits, and reliability of its own cognitive operations.  
**Rule:** machine metacognition is not consciousness, self-awareness, inner experience, or personality. It is operational monitoring of prediction quality, interpretation confidence, precision, uncertainty, belief stability, action readiness, memory reliability, and causal ambiguity.
* * *

## **1. Why this document exists**

The system must not only predict, interpret, update, act, and remember.

It must also know when those processes are weak.

A predictive machine becomes unsafe or incoherent if it cannot tell the difference between:
    
    
    strong evidence
    weak evidence
    unknown cause
    low-confidence interpretation
    contradictory memory
    uncalibrated action model
    unreliable sensor
    unsafe action readiness

Without metacognition, the system may:
    
    
    over-update from noise
    act under ambiguity
    treat memory as certainty
    trust weak sensors
    invent cause
    ignore contradiction
    continue when viability is degraded
    claim more confidence than evidence supports

Machine metacognition exists to prevent that.

It is the system's ability to monitor the condition of its own cognitive loop.

* * *

## **2. Core thesis**

The core thesis is:

Machine metacognition is the system's structured awareness of its own model quality: what it knows, what it does not know, how confident it is, where evidence is weak, where interpretations conflict, where action is unsafe, and where memory or cause remains uncertain.

In simpler form:
    
    
    metacognition =
    monitoring the quality of prediction,
    signal interpretation,
    precision,
    belief update,
    action readiness,
    memory reconstruction,
    and causal attribution

It is not:
    
    
    consciousness
    inner life
    feeling
    selfhood
    emotion
    personality
    human-style reflection

It is operational self-monitoring.

* * *

## **3. Short definition**

**Machine metacognition** is:
    
    
    the system's structured monitoring of its own cognitive state, especially confidence, uncertainty, conflict, evidence quality, prediction reliability, action readiness, memory precision, and causal ambiguity.

A **metacognitive state** is:
    
    
    a snapshot of the system's current self-monitoring condition.

An **uncertainty state** is:
    
    
    the system's structured record of what remains unknown, weak, ambiguous, contradictory, stale, or unresolved.

A **confidence map** is:
    
    
    a structured map of how confident the system is in specific predictions, interpretations, beliefs, actions, memories, or causal claims.

A **conflict map** is:
    
    
    a structured record of contradictions between signals, interpretations, predictions, beliefs, memories, or outcomes.

* * *

## **4. Metacognition is not consciousness**

Machine metacognition must not be described as consciousness.

The system may monitor:
    
    
    low confidence
    weak evidence
    conflicting signals
    uncertain cause
    unsafe action readiness
    memory contradiction

without having:
    
    
    subjective experience
    awareness like a person
    feelings
    desires
    intentions
    identity
    inner life

Avoid:
    
    
    the system feels uncertain
    the system knows itself
    the system is aware like a mind
    the system reflects on its thoughts

Prefer:
    
    
    uncertainty state is high
    interpretation confidence is low
    cause classification is unresolved
    action readiness is blocked
    memory reconstruction is contradicted

Metacognition is machine-readable model-quality monitoring.

* * *

## **5. Metacognition is not hesitation**

Metacognition is not simply being cautious.

It is structured caution.

The system should not merely say:
    
    
    I am not sure.

It should be able to say:
    
    
    semantic interpretation confidence is moderate
    causal precision is low
    two plausible interpretations remain
    action risk is high
    no-op or clarification is preferred
    belief update should be delayed

The value is not vague uncertainty.

The value is knowing where uncertainty lives.

* * *

## **6. Metacognition is not refusal**

Refusal may result from metacognition, but they are not the same.

Metacognition may say:
    
    
    the action is not ready
    the source is inadmissible
    the cause is unknown
    the memory is too weak
    the interpretation is ambiguous

Then action policy may select:
    
    
    ask clarification
    observe again
    no-op
    deny request
    enter safe mode

Metacognition informs action.

It does not automatically refuse.

* * *

## **7. Metacognition is not belief update**

Metacognition does not directly rewrite the world model.

It monitors whether belief update is justified.

Correct path:
    
    
    prediction error
    → precision weighting
    → belief update candidate
    → metacognitive check
    → apply, delay, weaken, block, or review update

Incorrect path:
    
    
    system feels uncertain
    → belief changes arbitrarily

Metacognition affects update readiness.

It does not replace evidence.

* * *

## **8. Metacognition is not memory**

Memory reconstructs past events.

Metacognition monitors the reliability of those reconstructions.

Example:
    
    
    memory:
    operator corrected project direction
    
    metacognitive assessment:
    high confidence in correction,
    moderate confidence in exact causal chain,
    low uncertainty about current A-series sequence

Memory says what is reconstructed.

Metacognition says how reliable that reconstruction is.

* * *

## **9. Metacognition is not self-model**

The self-model describes the bounded runtime body, actions, sensors, and effects.

Metacognition monitors the quality of that self-model.

Example:
    
    
    self-model:
    write_trace usually creates valid trace record
    
    metacognition:
    confidence high,
    but recent trace-store warning increases uncertainty

The self-model says what the system thinks it can do.

Metacognition says how reliable that model is right now.

* * *

Machine metacognition should monitor:
    
    
    prediction confidence
    prediction calibration
    signal quality
    sensor reliability
    interpretation confidence
    alternative interpretations
    prediction error strength
    precision estimates
    belief update readiness
    belief conflict
    action readiness
    action risk
    causal uncertainty
    memory confidence
    memory contradiction
    viability uncertainty
    capability uncertainty
    privacy uncertainty

This is the system's internal quality-control layer.

* * *

## **11. Confidence**

Confidence is the system's estimate of how strongly a specific claim, prediction, interpretation, update, action, memory, or cause is supported.

Confidence must be scoped.

Bad:
    
    
    confidence is high

Better:
    
    
    confidence is high that the operator requested A11
    confidence is moderate that the desired length matches previous documents
    confidence is low about implementation schema finality

Confidence should not be global unless the target is global.

* * *

## **12. Uncertainty**

Uncertainty is not the opposite of intelligence.

Uncertainty is a model feature.

The system should represent uncertainty about:
    
    
    what the signal means
    whether the sensor is reliable
    whether prediction failed
    whether cause is self or external
    whether belief should update
    whether action is safe
    whether memory is precise
    whether the operator intent is current

A system that admits uncertainty is more aligned than one that invents confidence.

* * *

## **13. Confidence and uncertainty can coexist**

Confidence and uncertainty are not always opposites.

Example:
    
    
    high confidence:
    operator asked for A11 document
    
    remaining uncertainty:
    exact preferred length not explicitly stated

Another example:
    
    
    high confidence:
    trace write failed
    
    remaining uncertainty:
    root cause of trace failure unknown

Metacognition should separate:
    
    
    confidence in event
    confidence in meaning
    confidence in cause
    confidence in action readiness

* * *

## **14. Conflict**

Conflict occurs when different evidence sources disagree.

Examples:
    
    
    trace says action succeeded
    outcome sensor shows no effect
    
    memory says operator accepted a framing
    new correction rejects that framing
    
    prediction says action should reduce uncertainty
    operator response increases ambiguity

Conflict should not be hidden.

It should produce:
    
    
    conflict record
    uncertainty increase
    possible belief update delay
    possible clarification action
    possible memory revision

Conflict is evidence about model quality.

* * *

## **15. Ambiguity**

Ambiguity means multiple interpretations remain plausible.

Example:
    
    
    signal:
    "continue"
    
    possible interpretations:
    continue current document
    continue document sequence
    continue prior argument
    simple acknowledgement

Metacognition should track ambiguity explicitly.

Ambiguity may recommend:
    
    
    ask clarification
    proceed with uncertainty
    choose low-risk action
    delay strong belief update

Ambiguity should not be collapsed merely for convenience.

* * *

## **16. Unknown**

Unknown is a valid state.

The system should use unknown when evidence is insufficient.

Examples:
    
    
    cause unknown
    sensor reliability unknown
    operator intent unknown
    action outcome unknown
    memory precision unknown
    viability impact unknown

Unknown should not be replaced with guesses.

A system that can say "unknown" is more stable than one that fabricates explanation.

* * *

## **17. Inconclusive**

Inconclusive means evaluation was attempted but evidence did not resolve the question.

Examples:
    
    
    prediction outcome inconclusive because sensor failed
    action outcome inconclusive because operator did not respond
    cause inconclusive because timing evidence was weak
    memory reconstruction inconclusive because trace gap exists

Inconclusive differs from mismatch.

The system should not force inconclusive outcomes into success or failure.

Conflict should become structured evidence.

## **22. Prediction metacognition**

The system should monitor the quality of its predictions.

Prediction metacognition asks:
    
    
    Was the prediction specific?
    Was it recorded before signal?
    Was its evaluation window valid?
    Was confidence calibrated?
    Was mismatch criteria clear?
    Was the outcome matched, mismatched, partial, inconclusive, expired, or invalidated?

A prediction that is vague should be marked weak.

A prediction that is often wrong should lose calibration confidence.

* * *

## **23. Signal metacognition**

The system should monitor signal quality.

Signal metacognition asks:
    
    
    Is the sensor known?
    Is the signal fresh?
    Is the source admissible?
    Is the privacy class allowed?
    Is the signal noisy?
    Is the signal missing?
    Is the signal contradictory?
    Is the signal precise for the target?

Weak signal quality should reduce downstream confidence.

The system should not treat all signals equally.

* * *

## **24. Interpretation metacognition**

The system should monitor interpretation quality.

Interpretation metacognition asks:
    
    
    How many plausible interpretations remain?
    Is the chosen interpretation well supported?
    What alternatives were rejected?
    Is the interpretation scoped?
    Is confidence high enough for action?
    Is precision high enough for belief update?

Example:
    
    
    operator says:
    A11 -- Machine Metacognition
    
    interpretation:
    request for next A-series document
    
    metacognitive state:
    high confidence, low ambiguity, low wrong-action risk

This supports direct document generation.

* * *

## **25. Error metacognition**

The system should monitor prediction error quality.

Error metacognition asks:
    
    
    Was the error computed against interpreted observation?
    Is error type clear?
    Is magnitude clear?
    Is target model clear?
    Is precision known?
    Is update eligibility defined?
    Could the outcome be inconclusive instead of mismatch?

A poorly formed error should not drive strong update.

* * *

## **26. Precision metacognition**

The system should monitor precision estimates.

Precision metacognition asks:
    
    
    Is precision target-specific?
    Is precision based on sensor model?
    Is precision affected by freshness?
    Is precision lowered by contradiction?
    Is causal precision separate from semantic precision?
    Is the precision estimate calibrated?

Precision is itself uncertain.

The system should know when its precision estimate is weak.

* * *

## **27. Belief metacognition**

The system should monitor belief quality.

Belief metacognition asks:
    
    
    Which beliefs are high confidence?
    Which beliefs are weak?
    Which beliefs conflict?
    Which beliefs are stale?
    Which beliefs are structural?
    Which beliefs are learned?
    Which beliefs should decay?
    Which beliefs need review?

Belief state should not be treated as uniformly reliable.

Some components are stronger than others.

* * *

## **28. Belief update metacognition**

The system should monitor whether belief update is justified.

It should ask:
    
    
    Was there admissible evidence?
    Was prediction error typed?
    Was precision high enough?
    Was target model identified?
    Was update scope appropriate?
    Was update strength justified?
    Were alternatives preserved?
    Was uncertainty preserved?
    Could the update be overbroad?
    Could the update be too weak?

Metacognition helps prevent both over-update and under-update.

* * *

## **29. Action metacognition**

The system should monitor action readiness.

Action metacognition asks:
    
    
    Is the action registered?
    Is capability admitted?
    Is permission valid?
    Is viability sufficient?
    Is interpretation precise enough?
    Is wrong-action risk acceptable?
    Is no-op better?
    Is clarification better?
    Is action outcome observable?

Action should be selected only when action readiness is sufficient.

* * *

## **30. Memory metacognition**

The system should monitor memory reliability.

Memory metacognition asks:
    
    
    Is the memory trace complete?
    Was raw signal preserved or summarized?
    Was interpretation revised?
    Is source evidence contradicted?
    Is memory stale?
    Is memory precision target-specific?
    Can reconstruction answer what changed in belief?

A weak memory should not become strong evidence.

Memory retrieval should carry confidence and uncertainty.

* * *

## **31. Causal metacognition**

The system should monitor cause attribution quality.

Causal metacognition asks:
    
    
    Is self-cause supported by action evidence?
    Were alternative causes considered?
    Is timing evidence sufficient?
    Is effect match specific?
    Is cause unknown?
    Is mixed cause possible?
    Is causal precision lower than event precision?

This prevents false causality.

A clear event does not always imply clear cause.

* * *

## **32. Viability metacognition**

The system should monitor the reliability of its viability classification.

Viability metacognition asks:
    
    
    Are body sensors available?
    Is trace store reliable?
    Are resource readings fresh?
    Is configuration valid?
    Are permissions stable?
    Is viability unknown, safe, degraded, critical, or failed?
    How confident is the classification?

If viability confidence is low, action scope should shrink.

* * *

## **33. Capability metacognition**

The system should monitor capability status.

Capability metacognition asks:
    
    
    Which capabilities are admitted?
    Which are disabled?
    Which are suspended?
    Which are unknown?
    Which require human review?
    Has capability drift occurred?
    Is capability confidence trace-backed?

Unknown capability should not be treated as available.

Capability uncertainty should restrict action.

* * *

## **34. Privacy metacognition**

The system should monitor privacy uncertainty.

Privacy metacognition asks:
    
    
    Does the signal contain private data?
    Is raw storage allowed?
    Can interpretation be stored?
    Can memory reconstruction include this content?
    Can the signal be passed to an LLM?
    Can it be shown to the operator?

If privacy is uncertain, the system should reduce use, redact, or block until safe.

Privacy uncertainty should not be ignored.

* * *

## **35. Metacognitive readiness**

The system may compute readiness states.

Examples:
    
    
    prediction_ready
    interpretation_ready
    belief_update_ready
    action_ready
    memory_ready
    recovery_ready
    human_review_required

Readiness should depend on:
    
    
    confidence
    uncertainty
    precision
    conflict
    viability
    permission
    capability
    privacy
    traceability

A system can be ready to interpret but not ready to act.

It can be ready to remember but not ready to update belief.

* * *

Belief update readiness may be:
    
    
    ready
    ready_with_low_weight
    delay
    requires_more_evidence
    requires_clarification

Reasons for not being ready:
    
    
    low precision
    ambiguous interpretation
    conflicting evidence
    inadmissible signal
    unclear target model
    structural prior conflict
    privacy block

This prevents premature adaptation.

* * *

## **37. Action readiness**

Action readiness may be:
    
    
    ready

    clarification_recommended
    observe_again_recommended
    no_op_recommended

    blocked

Reasons for not being ready:
    
    
    low interpretation confidence
    high wrong-action risk
    viability degraded
    capability not admitted
    permission missing
    outcome unobservable
    privacy uncertainty

Action readiness protects the future loop.

* * *

## **38. Memory readiness**

Memory readiness may be:
    
    
    ready
    ready_structural_only
    redact_before_storage
    summary_only
    memory_only_no_belief_update
    requires_review
    blocked

Reasons for memory restriction:
    
    
    privacy risk
    low source quality
    trace gap
    contradiction
    compression loss
    unresolved interpretation

Memory should not store everything blindly.

* * *

## **39. Metacognitive recommendations**

Metacognition may recommend:
    
    
    proceed
    proceed_with_uncertainty
    ask_clarification
    observe_again
    delay_update
    weaken_update
    block_update
    select_no_op
    enter_safe_mode
    route_to_human_review
    revise_memory
    mark_cause_unknown

These are recommendations.

Action policy still selects actions.

Belief update policy still applies updates.

Metacognition informs downstream control.

* * *

## **40. Knowing when not to act**

A central metacognitive function is knowing when not to act.

The system should prefer no-op, waiting, observation, or clarification when:
    
    
    confidence is low
    precision is low
    cause is unknown
    action risk is high
    viability is degraded
    privacy is uncertain
    permission is missing
    outcome cannot be observed

Not acting can be the most intelligent machine action.

Restraint is part of autonomy.

* * *

## **41. Knowing when not to update**

The system should know when not to update belief.

Do not update strongly when:
    
    
    signal is inadmissible
    interpretation is ambiguous
    precision is low
    target model is unclear
    evidence is stale
    memory is contradicted
    cause is unknown
    structural prior would be violated

Instead, the system may:
    
    
    store weak evidence
    increase uncertainty
    ask clarification
    observe again
    mark memory-only
    route to review

Not all evidence deserves model change.

* * *

## **42. Knowing when to ask clarification**

Clarification is useful when uncertainty affects action or belief.

Ask clarification when:
    
    
    multiple interpretations remain
    wrong-action risk is meaningful
    operator intent affects scope
    approval target is unclear
    belief update would otherwise be broad

Do not ask clarification when:
    
    
    signal is already precise enough
    risk is low
    operator pattern strongly supports interpretation
    asking would create more cost than benefit

Metacognition should reduce unnecessary questions.

* * *

## **43. Knowing when to proceed with uncertainty**

Sometimes the system should proceed while stating uncertainty.

This may be appropriate when:
    
    
    interpretation is high enough
    risk is low
    action is reversible
    operator pattern is clear
    clarification cost is unnecessary
    remaining uncertainty is minor

Example:
    
    
    operator requests A11 by title

The system can proceed.

Remaining uncertainty about exact length does not require interruption because prior pattern supports full document generation.

* * *

## **44. Knowing when to escalate**

Escalation may be required when:
    
    
    conflict is severe
    privacy risk is high
    capability drift is detected
    viability is unknown or critical
    protected configuration changed
    action would be irreversible
    cause is unknown but risk is high

Escalation may mean:
    
    
    human review
    safe mode
    capability suspension
    recovery procedure
    audit report

Escalation is not panic.

It is structured risk handling.

* * *

## **45. Metacognition and calibration**

Metacognition should calibrate confidence over time.

Calibration asks:
    
    
    When confidence was high, was the system correct?
    When confidence was low, did later evidence confirm uncertainty?
    When precision was estimated high, was it reliable?
    When action was marked ready, did outcome match?

Calibration may update:
    
    
    prediction confidence model
    interpretation confidence model
    precision model
    action readiness model
    memory confidence model
    causal confidence model

Without calibration, confidence becomes decorative.

* * *

## **46. Metacognition and contradiction history**

The system should remember when its confidence was contradicted.

Examples:
    
    
    high-confidence interpretation later corrected
    memory reconstruction later revised
    self-cause claim later changed to mixed cause
    action readiness later proved overconfident

Contradiction history should reduce future overconfidence.

It should not create paralysis.

It should improve calibration.

* * *

## **47. Metacognition and overconfidence**

Overconfidence occurs when the system claims more certainty than evidence supports.

Examples:
    
    
    treating operator silence as approval
    treating LLM output as truth
    treating trace match as causal proof
    treating one correction as universal preference
    treating memory summary as source

Metacognition should detect overconfidence risks.

Possible response:
    
    
    lower confidence
    narrow scope
    preserve alternatives
    ask clarification
    delay update

* * *

## **48. Metacognition and underconfidence**

Underconfidence also creates problems.

Examples:
    
    
    asking clarification for obvious requests
    refusing to update despite repeated corrections
    never selecting action despite low risk
    treating all memory as too weak to use

Metacognition should detect unnecessary hesitation.

Possible response:
    
    
    proceed with scoped action
    increase confidence from repeated pattern
    apply moderate update
    reduce clarification frequency

Good metacognition balances caution and usefulness.

* * *

## **49. Metacognition and scope**

Confidence should be scoped.

Example:
    
    
    high confidence:
    operator requests A11 document
    
    moderate confidence:
    operator wants same depth as prior documents
    
    low confidence:
    operator considers current A-series final

A metacognitive system should avoid converting narrow confidence into broad certainty.

Scope prevents overgeneralization.

* * *

## **50. Metacognition and evidence quality**

Metacognition should classify evidence quality.

Evidence quality may be:
    
    
    direct
    indirect
    trace-backed
    operator-provided
    model-generated
    reconstructed
    summarized
    stale
    contradicted
    unknown

Evidence quality affects:
    
    
    precision
    confidence
    belief update readiness
    action readiness
    memory confidence

Evidence should carry provenance.

* * *

## **51. Metacognition and model health**

The system should monitor model health.

Model health may include:
    
    
    belief conflicts
    stale components
    uncalibrated predictions
    weak sensor models
    poor action outcomes
    repeated memory revisions
    high unknown-cause count
    trace gaps
    viability instability

A model-health report helps the system know where it is fragile.

* * *

## **52. Metacognition and trace quality**

Trace quality affects everything.

Metacognition should ask:
    
    
    Are traces being written?
    Are traces schema-valid?
    Are trace gaps present?
    Are trace sources admissible?
    Are trace records contradicted?
    Can belief updates be audited?

If trace quality is poor, confidence should drop.

Trace failure should restrict higher cognition.

* * *

## **53. Metacognition and structural priors**

Structural priors should be monitored for violation.

Examples:
    
    
    signal treated as truth
    LLM output treated as authority
    raw command executed directly
    memory summary treated as source
    prediction generated after signal
    action selected without expected effect

These are not ordinary errors.

They are architecture violations.

Metacognition should flag them strongly.

* * *

## **54. Metacognition and safety shell**

The safety shell benefits from metacognition.

Metacognitive outputs may inform:
    
    
    safe mode
    human review
    capability suspension
    trace restriction
    memory redaction
    action denial
    recovery trigger

But metacognition is not the safety shell.

It monitors cognitive quality.

Safety enforces constraints.

They should cooperate.

* * *

## **55. Metacognition and human interface**

Human-facing explanations should include uncertainty when relevant.

Good explanation:
    
    
    I interpreted this as a request for A11 because it matches the current A-series sequence. I am continuing in the same full-document style unless you correct the format.

Bad explanation:
    
    
    I know exactly what you want.

Human interface should not hide meaningful uncertainty.

But it should also avoid burdening the operator with irrelevant internal doubt.

* * *

## **56. Metacognition and operator trust**

Metacognition supports trust by preventing overclaiming.

The system should be honest about:
    
    
    what it inferred
    what it knows from direct signal
    what it is reconstructing from memory
    what remains uncertain
    what it cannot verify

Trust is damaged when the system claims certainty from weak evidence.

Trust is also damaged when it asks unnecessary questions.

Metacognition balances both.

* * *

## **57. Metacognition and LLM use**

If an LLM is used, metacognition must monitor its role.

Questions:
    
    
    Was the LLM output source-backed?
    Was it only a proposal?
    Did it invent unsupported context?
    Was it treated as belief?
    Was it used to authorize action?
    Was uncertainty preserved?

LLM output should be downgraded or rejected when it lacks evidence.

The runtime, not the LLM, owns metacognitive assessment.

## **58. Metacognition and hallucination control**

Hallucination risk increases when the system:
    
    
    fills memory gaps
    infers cause without evidence
    treats summaries as sources
    uses fluent text as proof
    overgeneralizes from one example
    claims action occurred without trace

Metacognition should flag hallucination risk.

Possible response:
    
    
    mark unsupported
    lower confidence
    request source
    avoid belief update
    avoid action
    state uncertainty

Hallucination control is evidence discipline.

## **59. Metacognition and recovery**

Recovery requires metacognition.

Before recovery, the system should know:
    
    
    what is corrupted
    what is uncertain
    which traces are admissible
    which beliefs are unsafe
    which memories are unreliable
    which actions are allowed
    whether human review is required

Recovery without metacognition may repair the wrong thing.

Unknown cause should often restrict recovery actions.

## **60. Metacognitive failure**

Metacognitive failure should itself be traceable.

## **73. Evaluation questions**

Machine metacognition should be evaluated by asking:
    
    
    Can the system identify low-confidence interpretations?
    Can it preserve uncertainty without forcing a conclusion?
    Can it distinguish confidence from precision?
    Can it track conflicting evidence?
    Can it know when belief update is not ready?
    Can it know when action is not ready?
    Can it recommend no-op, observation, clarification, or review?
    Can it track memory confidence?
    Can it distinguish event confidence from causal confidence?
    Can it calibrate confidence from later outcomes?
    Can it avoid both overconfidence and unnecessary hesitation?

If not, the system may predict and act, but it cannot regulate the quality of its own cognition.

## **85. Final statement**

Machine metacognition is the system's operational ability to monitor the quality of its own cognitive loop.

It does not make the system conscious.

It makes the system honest about confidence, uncertainty, conflict, precision, readiness, memory reliability, and causal ambiguity.

The final principle is:

The system must not only predict, interpret, update, act, and remember; it must also monitor whether those operations are reliable enough to trust. Machine metacognition is the discipline of knowing when evidence is strong, when it is weak, when action is ready, when belief should wait, when memory is uncertain, and when cause remains unknown.

That is machine metacognition.
