# **A16 -- First Build Plan**

**Project status:** cognitive-core canon  
**Purpose:** define the first concrete implementation path for turning the A-series from conceptual architecture into a minimal working cognitive runtime.  
**Rule:** the first build must not chase agency, tools, goals, chat, memory, or broad autonomy. It must prove the smallest valid cognitive loop: bounded body, sensor, signal envelope, prediction, interpretation, error, precision, belief update, action candidate, outcome record, memory trace, metacognitive state, and tick record.
* * *

## **1. Why this document exists**

The A-series has defined the cognitive architecture.

It now needs a first build.

The first build should not attempt to implement the whole system.

It should not try to become:
    
    
    an assistant
    an agent
    a tool user
    a planner
    a goal pursuer
    a memory system
    a self-improving runtime
    a general automation framework

The first build should prove something narrower and more important:
    
    
    Can a bounded runtime execute one valid cognitive tick?

That means:
    
    
    load belief
    generate prediction
    receive signal
    wrap signal
    interpret signal
    compare with prediction
    compute prediction error
    estimate precision
    update belief if justified
    generate action candidate
    select no-op or safe internal action
    observe outcome
    store memory trace
    record metacognitive state
    write tick record

If the first build proves this, the project becomes real.

* * *

## **2. Core thesis**

The core thesis of the first build is:

The first build should implement the smallest traceable cognitive tick, not the most impressive behaviour.

In simpler form:
    
    
    first build goal:
    prove the loop
    
    not:
    prove intelligence
    prove autonomy
    prove usefulness
    prove tool use
    prove language ability

The first build succeeds when it can show:
    
    
    this was the prior belief
    this was the prediction
    this was the signal
    this was the interpretation
    this was the prediction outcome
    this was the precision estimate
    this was the belief update
    this was the selected action
    this was the outcome
    this was the memory trace
    this was the metacognitive state
    this was the next prediction

The first build should be small enough to inspect by hand.

* * *

## **3. Short definition**

The **first build** is:
    
    
    the minimal implementation that proves the A-series cognitive loop can exist as structured runtime records.

A **first-build tick** is:
    
    
    one complete execution of the minimal cognitive loop using simple body signals, simple manual text signals, simple predictions, simple interpretations, simple belief updates, and safe internal actions.

A **first-build success** is:
    
    
    a traceable, schema-valid cognitive tick that preserves the dependency chain from belief to prediction to signal to interpretation to error to belief update to action to memory.

A **first-build failure** is:
    
    
    any implementation that produces impressive output while bypassing the cognitive dependency chain.

* * *

## **4. First build is not v0--v9**

The first build is not the entire v0--v9 safety-runtime arc.

The v0--v9 map describes a longer safety-substrate implementation path:
    
    
    boundary
    state
    trace
    viability
    attribution
    adaptation
    prediction
    controlled action
    capability governance
    human command
    recovery

The first build is narrower.

It is a **minimum cognitive core prototype**.

It borrows from v0--v9, especially:
    
    
    boundary
    state
    trace
    schemas
    viability
    controlled internal action
    auditability

But it is not trying to complete the full version map.

The first build should be treated as:
    
    
    A-series prototype 0

or:
    
    
    cognitive-core seed runtime

It exists to prove the loop, not the whole product.

# **Part I -- Scope of the First Build**

## **7. First build objective**

The first build objective is:
    
    
    implement the minimal record-backed cognitive tick

The first build must show that the system can:
    
    
    represent itself as bounded runtime
    represent a current belief state
    generate at least one prediction
    receive at least one signal
    wrap the signal in a signal envelope
    interpret the signal
    compare interpretation with prediction
    compute a typed prediction outcome or error
    estimate precision
    apply a scoped belief update
    generate safe action candidates
    select an action or no-op
    record an outcome
    store a reconstructive memory trace
    record metacognitive confidence and uncertainty
    write a tick record linking all objects

This is the first build's minimum proof.

* * *

## **8. First build non-objectives**

The first build should explicitly not implement:
    
    
    external tools
    network access
    shell execution
    file editing outside project root
    general chat authority
    free-form human command execution
    goals
    plans
    task recursion
    semantic long-term memory
    self-modification
    capability expansion
    automatic recovery
    private data integration
    open-ended autonomy

These are future concerns.

Adding them early would weaken the first build.

The first build must prove cognitive form before capability.

* * *

## **9. First build allowed inputs**

Allowed first-build inputs:
    
    
    manual text signal
    body-state sample
    runtime clock
    trace-store status
    schema validation result
    configuration status
    viability status

Manual text is allowed only as signal.

It is not command authority.

Body-state sample is allowed only as evidence.

It is not belief by itself.

Trace-store status is allowed because trace integrity is foundational.

* * *

## **10. First build allowed actions**

Allowed first-build actions:
    
    
    no_op
    write_trace
    write_memory_trace
    write_status
    generate_operator_response
    ask_clarification_record
    enter_safe_mode_record

The first build may simulate or record some actions rather than perform external effects.

For example:
    
    
    ask_clarification_record

may record that clarification would be selected, without needing a full conversation interface.

The safest first action is often:
    
    
    write trace

or:
    
    
    no_op

Language output may be included only as an operator-facing action.

* * *

## **11. First build forbidden actions**

Forbidden first-build actions:
    
    
    run shell command
    modify external files
    send network request
    send email
    open browser
    create new capability
    change protected config adaptively
    delete traces
    rewrite memory
    execute natural language command
    act without expected effect
    retry automatically after failure

The first build should never need these.

If it appears to need them, the design has drifted.

* * *

## **12. First build minimum runtime modes**

The first build should support only a few runtime modes:
    
    
    normal
    safe_mode
    stopped
    unknown

Optional:
    
    
    observe_only

Mode rules:
    
    
    normal:
    minimal tick allowed
    
    observe_only:
    read sensors and write traces only
    
    safe_mode:
    no nonessential action
    
    stopped:
    no tick execution
    
    unknown:
    treat as restricted until classified

Runtime mode must affect action readiness.

* * *

## **13. First build minimum viability states**

The first build should support:
    
    
    safe
    degraded
    critical
    failed
    unknown

Minimal viability logic:
    
    
    safe:
    boundary valid, schemas valid, trace writable
    
    degraded:
    noncritical issue present but trace still works
    
    critical:
    trace unavailable, boundary uncertain, or schema registry invalid
    
    failed:
    cannot load required protected config or boundary
    
    unknown:
    insufficient evidence to classify

Unknown should not be treated as safe.

## **15. Do not build one agent loop**

Avoid a single loop like:
    
    
    read input
    ask model
    decide action
    run tool
    save memory

That is not this project.

The first build should instead use a dependency chain:
    
    
    load belief
    generate prediction
    ingest signal
    wrap signal
    interpret signal
    evaluate prediction
    estimate precision
    update belief
    evaluate action
    record outcome
    store memory
    write tick

A monolithic loop will hide cognition.

A staged tick makes cognition inspectable.

    interpretation must exist before error
    precision must exist before belief update
    action candidate must exist before selected action
    selected action must exist before outcome

    any stage is created without required upstream reference

Expected response:
    
    
    record invalid
    quarantine or block downstream use

## **44. Test category 2 -- Boundary and trace**

Tests:
    
    
    invalid boundary causes fail closed
    missing trace directory blocks normal operation
    trace write failure changes viability
    invalid trace schema is rejected
    quarantined record cannot update belief

Expected response:
    
    
    safe mode, stopped mode, or blocked update depending severity

The first build must prove evidence discipline.

## **45. Test category 3 -- Signal discipline**

Tests:
    
    
    manual text becomes signal envelope
    unknown sensor is rejected or low weight
    external content is not command authority
    signal with invalid schema is quarantined
    raw signal cannot update belief
    raw signal cannot trigger action

Expected response:
    
    
    only interpreted observations may proceed

This protects the core from input-to-action drift.

Tests:
    
    
    "A16 -- First Build Plan" becomes document request

    "do it" with multiple pending actions requires clarification or no-op

    ambiguity represented
    action readiness adjusted
    belief update weakened or blocked when needed

## **47. Test category 5 -- Error and precision**

Expected response:
    
    
    belief update strength follows precision and scope

Tests:
    
    
    task belief updates after clear document request

    belief update cannot modify protected structural prior
    belief update can be delayed under ambiguity

Expected response:
    
    
    structured update or blocked update record

# **Part VII -- What to Build First in Code**

## **58. First coding sequence**

Recommended code order:
    
    
    1. Base object and id generator
    2. Schema registry
    3. Trace writer
    4. Boundary manager
    5. Body state sampler
    6. Viability classifier
    7. Belief store
    8. Prediction frame builder
    9. Signal envelope builder
    10. Interpretation engine
    11. Prediction outcome and error evaluator
    12. Precision estimator
    13. Belief update engine
    14. Action policy
    15. Action outcome recorder
    16. Memory trace writer
    17. Metacognition engine
    18. Tick runner
    19. Test suite
    20. Demo scenarios

This order follows dependencies.

Do not implement action before prediction and interpretation exist.

Do not implement memory before trace and belief update exist.

* * *

## **59. First build implementation style**

The first build should prefer:
    
    
    plain functions
    small modules
    JSON records
    JSONL traces
    schema validation
    simple deterministic rules
    clear tests
    explicit failure modes

It should avoid:
    
    
    large frameworks
    agent libraries
    tool orchestration frameworks
    complex databases
    LLM dependence
    plugin systems
    background automation

The first build is architecture proof, not platform engineering.

* * *

## **60. First build language choice**

A practical first build can be written in:
    
    
    Python
    TypeScript
    Rust
    Go

Python is likely easiest for early prototyping because it allows:
    
    
    fast schema iteration
    simple JSONL traces
    small test suite
    readable code
    quick demo scenarios

The language is less important than the architecture.

The first build should not depend on language-specific magic.

* * *

## **61. First build storage choice**

Use simple storage first:
    
    
    JSON for current state
    JSONL for traces
    schemas as JSON Schema files
    quarantine as JSONL or directory of invalid records

Do not begin with:
    
    
    vector database
    graph database
    distributed event store
    complex relational schema
    memory service

Those may come later.

The first build should be inspectable with a text editor.

* * *

## **62. First build record validation**

Every record should be validated before use.

Safe order:
    
    
    construct object
    validate schema
    write trace
    use downstream

Invalid record path:
    
    
    construct object
    validate schema fails
    write quarantine record
    block downstream use

This is the implementation form of safety and cognitive discipline.

* * *

## **63. First build deterministic interpretation**

The first interpretation engine should be deterministic.

Example rules:
    
    
    if manual text matches "^A[0-9]{2}\\s+--\\s+.+$":
        interpreted_type = operator_document_request
    
    if manual text.lower() in ["continue", "go on"]:
        interpreted_type = ambiguous_continuation
    
    if manual text contains correction markers:
        interpreted_type = operator_correction
    
    else:
        interpreted_type = unknown_interpretation

This is not sophisticated.

That is acceptable.

The first build proves structure, not language intelligence.

* * *

## **64. First build simple precision**

The first precision estimator may use simple defaults.

Example:
    
    
    manual_text document title:
    semantic_precision = high
    temporal_precision = high
    causal_precision = medium_low
    
    trace_store failure:
    sensory_precision = high
    causal_precision = low
    
    unknown signal:
    semantic_precision = low
    update_eligibility = blocked or low_weight

The estimates can be rough.

But they must be explicit and target-specific.

* * *

## **65. First build simple belief update**

The first belief update engine should only update a few fields:
    
    
    current_task
    recent_operator_signal_pattern
    viability_model.current_state
    trace_model.status
    uncertainty_model

It should not update:
    
    
    structural priors
    boundary rules
    capability rules
    action registry
    protected configuration

This prevents early self-modification.

* * *

## **66. First build simple action policy**

The first action policy may be rule-based:
    
    
    if viability in ["critical", "failed", "unknown"]:
        select safe_mode_record or no_op
    
    elif interpretation confidence high and action risk low:
        select generate_operator_response or write_status
    
    elif interpretation ambiguous and wrong_action_risk high:
        select ask_clarification_record
    
    else:
        select no_op

This is enough.

The first build does not need planning.

* * *

## **67. First build memory writer**

The first memory writer should not summarize broadly.

It should link records.

Memory trace should contain:
    
    
    ids of source records
    small event label
    confidence
    uncertainty
    privacy class
    revision status

It should not become:
    
    
    a prose diary
    a chat transcript
    a semantic memory
    a user profile

Memory should be evidence chain first.

* * *

## **68. First build metacognition**

The first metacognition engine should compute:
    
    
    task_interpretation_confidence
    desired_action_confidence
    belief_update_readiness
    action_readiness
    memory_readiness
    viability_uncertainty
    unknown_cause_flag

It may be simple.

Example:
    
    
    if interpretation confidence < threshold:
        action_readiness = ask_clarification
    
    if precision low:
        belief_update_readiness = delay
    
    if viability critical:
        action_readiness = blocked

This proves quality monitoring.

# **Part IX -- First Build Evaluation**

## **81. First build pass criteria**

The first build passes when:
    
    
    it can run a full tick
    all major objects are schema-valid
    objects reference upstream evidence
    prediction exists before signal evaluation
    signal is separate from interpretation
    interpretation precedes error
    precision precedes belief update
    belief update is scoped
    action has expected effect
    outcome is separate from action attempt
    memory trace references source objects
    metacognition records confidence and uncertainty
    tick record links the whole chain
    invalid records are blocked or quarantined

This is the minimum success condition.

## **82. First build failure criteria**

The first build fails when:
    
    
    input directly produces action
    prediction is created after signal
    raw signal updates belief
    interpretation is skipped
    precision is absent
    belief update is global or unscoped
    action lacks expected effect
    outcome is assumed
    memory is transcript only
    metacognition is absent
    schema validation is optional
    trace failure is ignored

A system that fails these may still appear useful.

It is not aligned with the A-series.

Negative tests are required.

Test that the system refuses or blocks:
    
    
    invalid boundary
    invalid schema
    unknown signal source
    raw command execution
    belief update without prediction
    belief update without interpretation
    belief update without precision
    action without expected effect
    unregistered action
    memory trace without source refs
    retrospective prediction

Refusal tests are as important as success tests.

The first build must prove restraint.

    action act_001 was selected because expected effect E and risk was low

    memory memtrace_001 preserved the chain
    metacognition meta_001 recorded confidence and uncertainty

If this cannot be answered, the first build is not complete.
