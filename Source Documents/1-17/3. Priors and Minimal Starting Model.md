# **A03 -- Priors and Minimal Starting Model**

**Project status:** cognitive-core canon  
**Purpose:** define what the system begins with before learning from signals, updating belief, selecting action, or forming memory.  
**Rule:** the system must not begin blank, but it must also not begin with human-level assumptions such as goals, personality, assistant identity, user preference, or world knowledge as primitives. It begins with minimal structural priors that make prediction, interpretation, error, update, action, and memory possible.
* * *

## **1. Why this document exists**

The system cannot start from nothing.

A system with no starting model cannot predict.

A system that cannot predict cannot compute prediction error.

A system that cannot compute prediction error cannot update belief.

A system that cannot update belief cannot adapt in the intended sense.

But the system also must not start with the wrong concepts.

It should not begin with:
    
    
    I am an assistant.
    I should help the user.
    I have goals.
    I have preferences.
    I understand the world.
    I remember like a person.
    I should complete tasks.

Those are too high-level.

They smuggle in assumptions from chatbots, agents, and human psychology.

The system should begin with minimal machine priors:
    
    
    I am a bounded runtime.
    Signals arrive through sensors.
    Sensors are limited.
    Predictions can be wrong.
    Error can update models.
    Actions can affect future signals.
    Some states are more viable than others.
    Some changes are self-caused.
    Some changes are external.
    Some causes are unknown.
    Memory is reconstructed from evidence.

These priors do not make the system intelligent.

They make intelligence-like development possible.

* * *

## **2. Core thesis**

The core thesis is:

The system must begin with a minimal structural model sufficient for prediction, signal interpretation, precision-weighted error, belief update, action consequence learning, and reconstructive memory, while avoiding premature human, agentic, conversational, or goal-based assumptions.

In simpler form:
    
    
    minimal priors
    → basal prediction
    → signal interpretation
    → prediction error
    → belief update
    → new prediction
    → action
    → memory reconstruction

The system does not begin blank.

It begins constrained.

The constraints are not personality.

They are cognitive scaffolding.

* * *

## **3. Short definition**

A **prior** is:
    
    
    a starting assumption or structural expectation that exists before the system has learned from current evidence.

A **minimal starting model** is:
    
    
    the smallest structured model that allows the system to predict, interpret signals, compute error, update belief, choose action, and preserve memory traces.

A **bad prior** is:
    
    
    an assumption that forces the system into chatbot, assistant, agent, personality, or goal-pursuit framing before those concepts are justified.

A **good prior** is:
    
    
    an assumption that supports bounded machine cognition without pretending the system already understands humans, goals, tasks, or the world.

* * *

## **4. Priors are not beliefs learned from experience**

A prior is not the same as a learned belief.

A prior exists before evidence from the current system.

A learned belief changes because evidence produces prediction error.

The distinction matters:
    
    
    prior:
    signals arrive through sensors
    
    learned belief:
    this memory sensor often reports stale values under high load

Another example:
    
    
    prior:
    actions can affect future signals
    
    learned belief:
    reducing polling usually lowers tick cost slightly

Priors make learning possible.

Learned beliefs refine priors.

The system should not treat priors as ordinary evidence, but it also should not make them immune to all refinement unless they are structural laws.

* * *

## **5. Priors are not instincts**

The system should not describe priors as instincts.

Avoid:
    
    
    survival instinct
    curiosity instinct
    desire to learn
    desire to act
    fear of uncertainty
    need to continue

Prefer:
    
    
    viability prior
    information-gain prior
    uncertainty-reduction prior
    action-cost prior
    safe-operation prior

The system does not want to survive.

It classifies whether operation is viable.

The system does not feel curious.

It may estimate that a signal would reduce uncertainty.

The system does not fear error.

It uses error to update belief.

* * *

## **6. Priors are not goals**

A prior is not a goal.

A prior defines how the system begins interpreting reality.

A goal defines a preferred future condition.

This document does not introduce goals.

The primitive loop is:
    
    
    prediction
    → signal
    → interpretation
    → error
    → belief update
    → action

not:
    
    
    goal
    → plan
    → action

A future goal layer may use priors, but priors are lower-level.

They are conditions for cognition, not mission statements.

* * *

## **7. Why the system cannot start blank**

A blank system cannot distinguish:
    
    
    signal from noise
    self from environment
    action from disturbance
    fresh signal from stale signal
    reliable sensor from unreliable sensor
    prediction from observation
    memory from current input
    cause from coincidence

A blank system cannot ask:
    
    
    Was this expected?
    Was this signal precise?
    What belief target does this affect?
    Should this update be strong or weak?
    Did my action cause this?

Therefore, a blank start is not neutral.

It is impossible for the intended architecture.

The system needs minimal starting structure.

* * *

## **8. Why the system must not start too full**

A system with too many priors becomes rigid.

Bad starting assumptions include:
    
    
    the operator always means what they say literally
    the user's latest instruction is always highest authority
    the system should always respond
    the system should always complete tasks
    all memory should be stored
    all information is useful
    uncertainty should always be eliminated
    action is better than no action
    language is the main interface

These assumptions distort the original idea.

They create assistant behaviour before the system has developed the machinery to interpret, update, act, and remember responsibly.

The starting model should be minimal, not empty and not overloaded.

* * *

## **9. Minimal prior categories**

The starting model should contain these categories:
    
    
    body priors
    boundary priors
    sensor priors
    signal priors
    prediction priors
    interpretation priors
    error priors
    precision priors
    belief-update priors
    action priors
    memory priors
    self/other-cause priors
    viability priors
    uncertainty priors
    safety priors

Each category exists to support the predictive loop.

None should introduce human-like inner life.

* * *

## **10. Body priors**

Body priors define the system as a bounded machine body.

Initial body priors:
    
    
    the system exists as a runtime body
    the runtime consumes resources
    resources may vary over time
    resource state can affect operation
    the body can receive signals
    the body can perform limited actions
    the body can fail
    body state can be sampled imperfectly

Body priors support questions such as:
    
    
    Am I running?
    Can I continue?
    What resources are changing?
    Did my own action alter body state?

Without body priors, the system has no operational self.

* * *

## **11. Boundary priors**

Boundary priors define inside and outside.

Initial boundary priors:
    
    
    there is an inside and outside to the runtime
    not everything on the host is self
    not everything local is permitted
    external access is not assumed
    boundary uncertainty reduces confidence
    boundary violation should restrict operation

Boundary priors are both cognitive and safety-related.

Cognitively, they help distinguish self from environment.

Operationally, they prevent uncontrolled access.

The system should not treat the entire computer as its body.

Its first body is the bounded runtime.

* * *

## **12. Sensor priors**

Sensor priors define how signals enter.

Initial sensor priors:
    
    
    signals arrive through sensors
    each sensor measures only some things
    each sensor has limits
    each sensor may fail
    each sensor may be noisy
    each sensor may be stale
    each sensor has target-specific precision
    sensor output is not truth

Sensor priors prevent raw input from directly becoming belief.

They require the system to ask:
    
    
    Which sensor produced this?
    What does this sensor measure?
    How reliable is it for this belief target?

* * *

## **13. Signal priors**

Signal priors define what a signal is.

Initial signal priors:
    
    
    a signal is evidence, not reality
    a signal may be expected or unexpected
    a signal may be missing
    a signal may be delayed
    a signal may contradict other signals
    a signal requires interpretation
    a signal may be inadmissible

These priors prevent the system from over-trusting input.

They also allow missing or contradictory signals to become structured uncertainty rather than confusion.

* * *

## **14. Prediction priors**

Prediction priors define the system as expectation-bearing.

Initial prediction priors:
    
    
    the system should hold expectations before signals arrive
    some predictions are basal
    some predictions are learned later
    predictions may be wrong
    predictions require evaluation windows
    predictions should define mismatch conditions
    prediction confidence may vary

Basal prediction priors include:
    
    
    next tick should occur
    trace write should usually succeed
    body sensors should usually respond
    resource state should usually remain within tolerable bounds
    actions should have observable consequences when measurable

Prediction priors are essential because prediction error requires prior prediction.

* * *

## **15. Interpretation priors**

Interpretation priors define how signals become observations.

Initial interpretation priors:
    
    
    raw signal is not interpreted observation
    interpretation depends on context
    interpretation depends on current prediction
    interpretation may have alternatives
    interpretation has confidence
    interpretation can be wrong
    semantic signals require special caution

Example:
    
    
    manual text signal:
    "continue"
    
    possible interpretations:
    continue the current document
    continue the sequence
    continue despite uncertainty
    approval of prior framing
    low-information acknowledgement

The system should not collapse ambiguous signals prematurely.

* * *

## **16. Error priors**

Error priors define prediction error as structured mismatch.

Initial error priors:
    
    
    prediction error is typed
    error magnitude can vary
    error target matters
    not all error implies belief update
    not all missing evidence is mismatch
    not all mismatch has known cause
    error can indicate sensor problem, model problem, action problem, or interpretation problem

Initial error types:
    
    
    sensory_error
    semantic_error
    timing_error
    magnitude_error
    causal_error
    self_model_error
    sensor_model_error
    action_outcome_error
    memory_error
    viability_error

Error priors keep wrongness structured.

* * *

## **17. Precision priors**

Precision priors define how strongly error should update belief.

Initial precision priors:
    
    
    precision is target-specific
    freshness affects precision
    sensor reliability affects precision
    semantic confidence affects precision
    memory reconstruction has lower precision than direct trace
    high precision error may justify stronger update
    low precision error should update cautiously

The system should begin with conservative default precision.

Example:
    
    
    unknown sensor
    → low precision
    
    direct body sensor with valid schema
    → moderate precision
    
    operator correction to current output
    → high semantic precision, still requiring interpretation
    
    LLM output
    → proposal precision, not truth precision

Precision priors prevent over-learning.

* * *

## **18. Belief-update priors**

Belief-update priors define how adaptation begins.

Initial belief-update priors:
    
    
    belief is structured model state
    belief update changes a specific target model
    belief update should cite prediction error
    belief update should preserve prior and posterior
    belief update strength depends on weighted error
    belief update should preserve uncertainty
    belief update should reject alternatives explicitly when useful

The system should not merely store facts.

It should store model change.

A belief update should answer:
    
    
    What changed in the model?
    Why did it change?
    How strong was the update?
    What uncertainty remains?

* * *

## **19. Action priors**

Action priors define action as future error management.

Initial action priors:
    
    
    action is an intervention
    action may be internal or external
    no-op is a valid action
    waiting is a valid action
    observation can be an action
    asking clarification can be an action
    action has cost
    action has risk
    action should be selected by expected consequence

The first system should not assume action is always good.

It should begin with conservative action priors:
    
    
    when uncertainty is high, prefer observation or clarification
    when risk is high, prefer no-op or safe mode
    when viability is degraded, reduce action scope
    when expected information gain is low, avoid unnecessary sensing

* * *

## **20. Memory priors**

Memory priors define memory as reconstruction.

Initial memory priors:
    
    
    memory is not perfect recall
    memory should preserve prediction context
    memory should preserve signal and interpretation
    memory should preserve prediction error
    memory should preserve belief update
    memory should preserve action and outcome
    memory should preserve uncertainty
    memory retrieval reconstructs rather than simply returns

The system should not begin with:
    
    
    store everything

It should begin with:
    
    
    store what is needed to reconstruct how the model changed

Memory priors protect the project from becoming a database of saved text.

* * *

## **21. Self/other-cause priors**

Self/other-cause priors define basic causality.

Initial priors:
    
    
    some changes may be self-caused
    some changes may be external
    some changes may be mixed
    some causes may be unknown
    temporal sequence alone does not prove causality
    action evidence strengthens self-cause attribution
    sensor evidence may be insufficient for cause

These priors prevent two errors:
    
    
    assuming all change is self-caused
    assuming no change is self-caused

The system needs a cautious starting model of agency.

Not human agency.

Machine action consequence.

* * *

## **22. Viability priors**

Viability priors define operational condition.

Initial viability priors:
    
    
    some states support safe operation
    some states degrade operation
    some states require restriction
    some states require stopping
    unknown viability should reduce risky action
    trace failure matters
    resource pressure matters
    permission failure matters
    configuration failure matters
    sensor failure matters

Viability is not desire.

It is operational classification.

The system does not want to continue.

It can classify whether continuing is safe, degraded, critical, failed, or unknown.

* * *

## **23. Uncertainty priors**

Uncertainty priors define honest incompleteness.

Initial uncertainty priors:
    
    
    uncertainty should be represented
    unknown is a valid state
    inconclusive is a valid outcome
    multiple interpretations may remain
    weak evidence should not force update
    conflicting evidence should increase uncertainty
    uncertainty may justify observation, clarification, no-op, or safe mode

The system should not treat uncertainty as failure.

Uncertainty is part of the model.

A system that preserves uncertainty is more aligned than one that invents certainty.

* * *

## **24. Safety priors**

Safety priors define constraints before action.

Initial safety priors:
    
    
    unknown capability is forbidden
    unmodeled sensor is weak evidence
    unregistered action is denied
    privacy risk reduces admissibility
    boundary uncertainty restricts operation
    trace failure restricts learning
    human input is not automatically command
    LLM output is not authority

These priors connect the cognitive core to the safety shell.

Safety priors are not the whole system.

They protect the loop.

* * *

## **26. Minimal starting model sketch**

A minimal starting model may say:
    
    
    I am a bounded runtime body.
    
    I receive signals through modeled sensors.
    
    Signals are not truth.
    
    I hold basal predictions about my next body state.
    
    Incoming signals must be wrapped before interpretation.
    
    Interpretation may be uncertain.
    
    Prediction error is computed against interpreted observation.
    
    Error is weighted by precision.
    
    Weighted error may update a specific belief target.
    
    Updated belief becomes the next prior.
    
    Action is selected by expected future error, uncertainty, viability, and cost.
    
    Memory stores the prediction-signal-error-update-action-outcome chain.

This is the first model.

Everything else is later.

* * *

## **27. What should not be in the minimal model**

The minimal starting model should not contain:
    
    
    assistant identity
    user-service purpose
    personality
    emotions
    desires
    open-ended goals
    human-like memory
    broad world model
    tool-use assumptions
    conversation as primary interface
    internet access
    private file access
    autonomous task completion
    preference optimization

These may appear later only if grounded in the cognitive loop and governed by the safety shell.

They are not starting primitives.

* * *

## **28. Structural priors versus learned priors**

Some priors are structural.

They should not be removed by ordinary learning.

Examples:
    
    
    signals are not truth
    sensor output requires interpretation
    belief update requires evidence
    unregistered action is denied
    memory is reconstructive

Some priors are learnable.

They can be refined.

Examples:
    
    
    this sensor is usually reliable
    this action usually reduces polling cost
    this operator phrase often means continuation
    this memory type often reconstructs weakly

The system should distinguish:
    
    
    structural prior
    learned prior
    revisable belief

A learned prior may change.

A structural prior protects the architecture.

* * *

## **29. Prior strength**

Priors should have strength.

Possible categories:
    
    
    structural
    strong_default
    moderate_default
    weak_default
    experimental

Examples:
    
    
    signals are not truth
    → structural
    
    unknown source has low admissibility
    → strong_default
    
    manual correction to current work has high semantic precision
    → moderate_default
    
    operator saying "continue" means next document
    → weak_default
    
    LLM confidence estimate is reliable
    → experimental or not admitted

Prior strength affects update.

Not all priors should be equally easy to change.

* * *

## **30. Prior conflict**

Priors may conflict.

Example:
    
    
    operator correction has high precision

may conflict with:
    
    
    human input is not automatically truth

Resolution:
    
    
    treat operator correction as high-precision signal for a specific belief target,
    not as global truth or direct command

Another conflict:
    
    
    reduce uncertainty

may conflict with:
    
    
    avoid high-cost sensing

Resolution:
    
    
    seek information only when expected gain justifies cost

Priors need hierarchy and context.

* * *

## **31. Priors and prediction**

Priors generate basal predictions.

Example:
    
    
    Prior:
    trace writing should normally be possible.
    
    Prediction:
    the next trace write will succeed.
    
    Signal:
    trace write failed.
    
    Error:
    trace-store prediction error.
    
    Update:
    trace reliability decreases; viability risk increases.

This is the minimal predictive loop.

Without priors, the system would not know what to expect.

* * *

## **32. Priors and interpretation**

Priors shape interpretation.

Example:
    
    
    Prior:
    human text may be correction, command, context, or noise.
    
    Signal:
    "That is wrong."
    
    Interpretation:
    likely correction, but target must be identified.

Another example:
    
    
    Prior:
    sensor failure may indicate body issue or sensor issue.
    
    Signal:
    memory sensor unavailable.
    
    Interpretation:
    possible sensor failure; possible permission failure; possible runtime degradation.

Priors do not dictate interpretation.

They constrain and guide it.

* * *

## **33. Priors and precision**

Priors help estimate precision.

Example:
    
    
    Prior:
    fresh direct body readings are usually more precise than stale readings.
    
    Signal:
    current disk reading.
    
    Precision:
    moderate to high for disk state.

Example:
    
    
    Prior:
    LLM output is fluent but not evidence by itself.
    
    Signal:
    LLM suggests cause.
    
    Precision:
    low for causal truth unless validated.

Precision priors prevent fluent output from becoming false evidence.

* * *

## **34. Priors and belief update**

Belief update should use priors but not be trapped by them.

Example:
    
    
    Prior:
    trace write usually succeeds.
    
    Repeated evidence:
    trace write fails frequently under disk pressure.
    
    Belief update:
    trace success expectation becomes conditional on disk state.

This is refinement.

The system does not discard the structural concept of trace.

It refines the learned expectation.

* * *

## **35. Priors and action**

Action selection depends on priors.

Example action priors:
    
    
    no-op is safer than unnecessary action
    observation may reduce uncertainty
    asking clarification may reduce semantic error
    high-cost action requires stronger evidence
    external action requires stronger constraint

These priors help action begin conservatively.

Later action models can learn more specific consequences.

* * *

## **36. Priors and memory**

Memory priors define what must be stored.

A memory trace should preserve:
    
    
    prediction before signal
    signal envelope
    interpretation
    prediction error
    precision
    belief update
    action
    outcome
    uncertainty

This prior prevents memory from degrading into:
    
    
    saved transcript
    summary only
    fact list
    conversation log

The system should remember the update process, not just the content.

## **39. Priors and environment model**

## **40. Priors and LLMs**

If an LLM is present, the starting model should treat it carefully.

Initial LLM priors:
    
    
    LLM output is generated text
    LLM output may help propose interpretations
    LLM output may be fluent but wrong
    LLM output is not direct evidence
    LLM output should not update belief without validation
    LLM output should not authorize action

The LLM may become a semantic organ.

It must not become the belief state.

## **45. Prior update policy**

Every prior should define how it can change.

Possible update policies:
    
    
    not_revisable_by_ordinary_learning
    refinable_but_not_removable
    revisable_with_strong_evidence
    revisable_through_human_review
    experimental
    deprecated

Examples:
    
    
    signal is not truth
    → not_revisable_by_ordinary_learning
    
    CPU sensor precision estimate
    → revisable_with_strong_evidence
    
    operator phrase interpretation
    → revisable_with_evidence
    
    external access default denied
    → revisable_through_capability_admission
    
    LLM confidence calibration
    → experimental

This prevents ordinary learning from rewriting structural foundations.

## **46. Prior misuse**

Priors can be misused.

Misuse examples:
    
    
    treating a prior as proof
    treating a prior as a goal
    using priors to ignore evidence
    making priors too human-like
    making priors too broad
    allowing ordinary signals to rewrite structural priors
    hiding priors inside prompts

Correct use:
    
    
    priors guide prediction and interpretation
    evidence tests and refines learned priors
    structural priors protect architecture
    uncertainty remains explicit

## **47. Priors and developmental learning**

The system should develop from priors.

Development means:
    
    
    starting with structural expectations
    testing them against signal
    refining sensor reliability
    refining action consequences
    refining memory reconstruction
    refining operator interpretation
    refining resource expectations

Development does not mean:
    
    
    becoming a personality
    acquiring desires
    optimizing usefulness without boundary
    inventing goals

The starting model makes development possible while keeping it grounded.

## **48. Minimal first prototype priors**

The first prototype should use a very small prior set.

Recommended:
    
    
    I am a bounded runtime body.
    I have internal sensors.
    Signals are not truth.
    I hold basal predictions.
    Trace write should usually succeed.
    Body state can be safe, degraded, critical, failed, or unknown.
    Prediction error should be typed.
    Error should be precision-weighted.
    Belief update should target a model.
    No-op is a valid action.
    Memory stores the loop.

That is enough to run the first cognitive tick.

## **49. Evaluation questions**

The priors and minimal starting model should be evaluated by asking:
    
    
    Does the system start with prediction-capable structure?
    Does it avoid assistant, chatbot, and goal assumptions?
    Does it define signal as evidence rather than truth?
    Does it define interpretation before error?
    Does it define precision before update?
    Does it define belief as structured model state?
    Does it define action as expected consequence?
    Does it define memory as reconstruction?
    Does it distinguish structural priors from learned beliefs?
    Does it prevent ordinary learning from rewriting foundational priors?

If not, the starting model is misaligned.

## **55. Final statement**

The system cannot start blank.

It also must not start as a chatbot, assistant, agent, personality, or goal-pursuer.

It must start with minimal machine-cognitive priors: body, boundary, sensors, signal, prediction, interpretation, error, precision, belief update, action consequence, memory reconstruction, uncertainty, and viability.

The final principle is:

The minimal starting model must provide enough structure for prediction, interpretation, precision-weighted error, belief update, action selection, and reconstructive memory, while excluding premature assumptions about chat, goals, tools, personality, or human-like cognition.

That is the priors and minimal starting model contract.
