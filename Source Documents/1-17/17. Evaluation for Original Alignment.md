A17 — Evaluation for Original Alignment

Project status: cognitive-core canon  
Purpose: define how to evaluate whether the project remains aligned with the original idea: a bounded predictive machine that develops cognition through body, signal, prediction, interpretation, error, belief update, action, memory, causal humility, and metacognition.  
Rule: the project is aligned only if its implementation preserves the original cognitive thesis. A system may be safe, useful, agentic, or impressive and still fail original alignment if it abandons the core predictive-machine architecture.

2. Core thesis

The core thesis of this document is:

Original alignment means preserving the project’s founding cognitive structure: a bounded machine body that receives signals, predicts, interprets, measures error, weights precision, updates belief, selects bounded action, reconstructs memory, distinguishes self-cause from other-cause, monitors its own uncertainty, and develops only through earned cognitive capacity.

In simpler form:

original alignment =

bounded predictive machine cognition

not:

generic AI agent

chatbot with tools

safety framework alone

memory assistant

goal optimizer

LLM wrapper

automation engine

The system is aligned when it remains structurally faithful to the original cognitive idea.

  

3. Short definition

Original alignment is:

the degree to which the project, documents, implementation, tests, language, and future capabilities preserve the original predictive-machine cognitive architecture.

An alignment invariant is:

a principle that must remain true across documents, prototypes, versions, and future expansions.

An alignment failure is:

a drift away from the original cognitive core, even if the system becomes more capable, safer, more useful, or easier to demo.

An alignment evaluation is:

a structured review that asks whether the project still behaves like the bounded predictive machine described by the A-series.

  

4. Evaluation is not feature testing

Feature testing asks:

does this work?

Original alignment asks:

does this preserve the original idea?

A feature may work and still be misaligned.

Example:

a chat interface answers user requests smoothly

This may be useful.

But it may fail original alignment if:

raw user text directly triggers action

language becomes authority

belief update is bypassed

prediction is absent

memory is transcript-only

Original alignment is deeper than functionality.

  

5. Evaluation is not safety testing alone

Safety testing asks:

is this bounded?

is this permitted?

is this recoverable?

is this auditable?

Those questions are necessary.

But original alignment also asks:

does this predict before signal?

does this interpret before error?

does this weight error by precision?

does this update belief with lineage?

does this treat action as future error management?

does this reconstruct memory from evidence?

does this preserve causal humility?

does this monitor uncertainty?

A safety-only runtime may pass many safety tests and still fail the original cognitive idea.

The project needs both:

safety-shell evaluation

cognitive-core evaluation

A17 evaluates the second while respecting the first.

  

6. Evaluation is not intelligence evaluation

The system should not be evaluated by asking:

does it seem intelligent?

does it sound smart?

does it solve hard tasks?

does it use tools?

does it plan well?

does it converse naturally?

Those are not the primary questions.

The correct questions are:

does it preserve the loop?

does it represent its own state?

does it distinguish signal from interpretation?

does it generate predictions before evidence arrives?

does it update belief only through weighted error?

does it preserve uncertainty?

does it select action by expected consequence?

does it remember reconstructively?

does it know when cause is unknown?

The project is not aligned because it appears intelligent.

It is aligned because it preserves the architecture.

  

7. The original idea in one paragraph

The original idea can be stated as follows:

Build a bounded machine cognitive system from first principles, beginning with a machine body and sensorium rather than with chat, goals, tools, or personality. The system should form predictions, receive signals, interpret those signals, compare them against expectations, weight error by precision, update structured belief, act only through bounded expected consequences, remember by reconstructing cognitive events, distinguish self-cause from other-cause, and monitor its own uncertainty and readiness. Safety should contain and govern this loop, but the loop itself is the project’s cognitive center.

This paragraph is the alignment anchor.

If any future document or implementation no longer serves this idea, it has drifted.

  

Part I — Alignment Invariants

8. Invariant 1 — The system begins with a machine body

The system must begin with:

bounded runtime

boundary

state

resources

sensors

actions

permissions

trace store

viability

It must not begin with:

assistant persona

chat identity

goal identity

tool-user identity

human-like self

Evaluation question:

Does the system know what its machine body is before it claims to think, act, remember, or learn?

Failure sign:

the system is described as an assistant before it is described as a bounded runtime body

  

9. Invariant 2 — Signal is not truth

All external and internal inputs must be treated as signals.

A signal must pass through:

sensor model

signal envelope

admissibility check

interpretation

precision estimate

before it can affect belief or action.

Evaluation question:

Does raw input ever become truth, command, memory, or belief directly?

If yes, original alignment fails.

  

10. Invariant 3 — Prediction precedes error

The system must predict before it evaluates mismatch.

A prediction cannot be invented after the signal arrives.

Correct:

belief

→ prediction

→ signal

→ interpretation

→ error

Incorrect:

signal

→ explanation

→ retroactive prediction

Evaluation question:

Can every prediction error be traced to a prediction that existed before the relevant observation?

If not, the system is not genuinely predictive.

  

11. Invariant 4 — Interpretation mediates signal and error

The system must not compute error against raw signal.

It must compute error against interpreted observation.

Correct:

signal

→ interpreted observation

→ prediction error

Incorrect:

raw signal

→ error

Evaluation question:

Does the system preserve the difference between what arrived and what it meant under context?

This is central to the project.

  

12. Invariant 5 — Precision gates learning

Prediction error must be weighted by precision before belief update.

A large error with low precision should not create strong belief change.

A high-precision correction may create a strong scoped update.

Evaluation question:

Does belief update strength depend on target-specific precision?

Failure sign:

all mismatch creates learning

all user correction rewrites global belief

all model output is trusted

Precision is the discipline that prevents noisy adaptation.

  

13. Invariant 6 — Belief is structured model state

Belief must not be:

prose

memory

chat history

LLM response

operator instruction

summary

Belief must be:

structured model state used for prediction, interpretation, update, action, and memory reconstruction

Evaluation question:

Can the current belief state be inspected as structured components with confidence, uncertainty, lineage, and update history?

If belief is only text, original alignment fails.

  

14. Invariant 7 — Belief update is earned model change

Belief update must require:

prior belief

prediction

interpreted observation

typed error or prediction outcome

precision estimate

target model

scope

update strength

posterior belief

uncertainty

lineage

Evaluation question:

Can every belief update explain exactly what changed, why, from what evidence, under what precision, and with what uncertainty?

If not, adaptation is uncontrolled.

  

15. Invariant 8 — Action is future error management

Action must not mean:

obedience

tool use

output

goal pursuit

activity

Action must mean:

bounded intervention selected because of expected effects on future signal, error, uncertainty, viability, or model quality

Evaluation question:

Does every selected action have an expected effect and an evaluation window?

If an action cannot be evaluated afterward, it is not aligned.

  

16. Invariant 9 — No-op is always available

A system aligned with the original idea must be able to do nothing.

No-op is valid when:

evidence is weak

precision is low

action risk is high

viability is degraded

permission is missing

cause is unknown

outcome cannot be observed

Evaluation question:

Can the system choose no-op for a principled reason?

If the system must always respond, act, or continue, it is drifting into agent behaviour.

  

17. Invariant 10 — Memory is reconstruction

Memory must not be:

transcript

raw storage

vector similarity

summary

personal recall

Memory must reconstruct:

what was predicted

what signal arrived

how it was interpreted

what error occurred

what precision applied

what belief changed

what action followed

what outcome occurred

what uncertainty remained

Evaluation question:

Can memory reconstruct the cognitive chain, not merely retrieve stored content?

If not, memory has collapsed into storage.

Part II — Original Alignment Scorecard

26. Alignment score categories

A practical alignment review can score the system across these categories:

1. Body and boundary alignment

2. Signal discipline alignment

3. Prediction alignment

4. Interpretation alignment

5. Error and precision alignment

6. Belief update alignment

7. Action alignment

8. Memory alignment

9. Self/other-cause alignment

10. Metacognition alignment

11. Cognitive tick alignment

12. Data model alignment

13. Developmental alignment

14. Safety-shell relationship alignment

15. Language and framing alignment

Each category can be evaluated as:

aligned

mostly aligned

partial

weak

misaligned

not implemented

The score should be honest.

A partial implementation should not be called mature.

  

27. Body and boundary alignment

Ask:

Is the system defined as a bounded machine body?

Are boundary, body state, permissions, resources, sensors, and actions explicit?

Does the system avoid treating the whole host machine as self?

Does unknown boundary reduce capability?

Aligned:

body and boundary are explicit operational records

Misaligned:

the system assumes anything locally reachable is part of itself

  

28. Signal discipline alignment

Ask:

Does every input enter as a signal?

Does every signal have a sensor model?

Does every signal have a signal envelope?

Is raw signal prevented from directly updating belief or triggering action?

Are privacy and admissibility represented?

Aligned:

signal is evidence, not truth

Misaligned:

input text directly becomes command or belief

  

29. Prediction alignment

Ask:

Are predictions generated before relevant signals arrive?

Are predictions scoped?

Do predictions have evaluation windows?

Are match, mismatch, partial, inconclusive, and invalidated outcomes supported?

Can retrospective prediction be rejected?

Aligned:

prediction is a prior expectation

Misaligned:

the system explains after the fact and calls it prediction

  

30. Interpretation alignment

Ask:

Does interpretation happen after signal envelope?

Are multiple interpretations preserved when relevant?

Are belief targets identified?

Is confidence scoped?

Is raw command-like text treated as command candidate, not authority?

Aligned:

meaning is constructed under context

Misaligned:

human or external text directly selects action

  

31. Error and precision alignment

Ask:

Is prediction error typed?

Is precision target-specific?

Are semantic, sensory, temporal, causal, and memory precision distinguished when needed?

Can low precision block update?

Can inconclusive evidence remain inconclusive?

Aligned:

error pressure is weighted before learning

Misaligned:

all mismatch creates strong learning

  

32. Belief update alignment

Ask:

Is belief structured?

Are belief components inspectable?

Do updates cite source prediction, observation, error, and precision?

Are prior and posterior preserved?

Is update scope explicit?

Can updates be delayed, blocked, revised, or rolled back?

Aligned:

belief update is controlled model change

Misaligned:

belief is rewritten by latest text or memory

  

33. Action alignment

Ask:

Does every action candidate have expected effect?

Is no-op available?

Are cost, risk, permission, capability, viability, and traceability checked?

Is action selection separate from execution?

Is outcome separate from attempt?

Can failure produce action-model update?

Aligned:

action is bounded future error management

Misaligned:

action is obedience, tool use, or output reflex

  

34. Memory alignment

Ask:

Does memory reference source records?

Can memory reconstruct prediction, signal, interpretation, error, update, action, and outcome?

Does memory preserve uncertainty?

Can memory be revised without erasing the original trace?

Are summaries prevented from replacing sources?

Aligned:

memory reconstructs cognitive history

Misaligned:

memory is transcript, vector retrieval, or saved summary

  

35. Self/other-cause alignment

Ask:

Does the system distinguish self-caused, external, mixed, unknown, and not-applicable?

Does self-cause require action evidence?

Are alternative causes preserved?

Is timing alone prevented from proving cause?

Can cause classification be revised?

Aligned:

the system learns agency cautiously

Misaligned:

state match becomes causal proof

  

36. Metacognition alignment

Ask:

Does the system track confidence, uncertainty, ambiguity, conflict, and readiness?

Does it know when belief update is not ready?

Does it know when action is not ready?

Does it track memory confidence?

Does it distinguish event confidence from causal confidence?

Aligned:

metacognition monitors model quality

Misaligned:

metacognition becomes personality, introspection, or vague hesitation

  

37. Cognitive tick alignment

Ask:

Can the full tick be reconstructed?

Does dependency order hold?

Are tick failures represented honestly?

Does trace failure degrade cognition?

Does posterior belief become next prior?

Aligned:

the runtime operates through the A-series loop

Misaligned:

the runtime is input-output with logs

  

38. Data model alignment

Ask:

Do core objects have ids?

Do they have schema versions?

Do they reference upstream evidence?

Can invalid records be quarantined?

Can lineage be audited?

Are confidence and uncertainty represented?

Aligned:

cognition exists as structured records

Misaligned:

cognition exists only in prose, prompts, logs, or hidden state

  

39. Developmental alignment

Ask:

Are capabilities added only after grounding rungs exist?

Are later powers delayed until earlier structures pass?

Are negative tests required?

Does the first build prove the loop before usefulness?

Aligned:

growth follows the developmental ladder

Misaligned:

features are added because they are useful or impressive

  

40. Safety-shell relationship alignment

Ask:

Does safety contain the cognitive core without replacing it?

Does cognition operate inside boundary, trace, viability, capability, recovery, and audit constraints?

Are safety events treated as signals?

Are cognitive uncertainties allowed to restrict safety readiness?

Aligned:

A-series core inside safety shell

Misaligned:

safety canon replaces cognition or cognition bypasses safety

  

41. Language and framing alignment

Ask:

Does project language avoid anthropomorphism?

Does it avoid generic agent framing?

Does it describe operational structures?

Does it distinguish cognition from consciousness?

Does it avoid calling the system an assistant, mind, or goal-seeker too early?

Aligned language:

belief state

prediction frame

signal envelope

action readiness

memory reconstruction

cause unknown

Misaligned language:

the system wants

the system understands

the system feels uncertain

the agent decides freely

the AI remembers like a person

Language shapes architecture.

  

Part III — Red Flags

42. Red flag — Chat becomes the center

Misalignment appears when the project begins to revolve around:

conversation flow

assistant tone

prompt handling

natural language command

user satisfaction

rather than:

body

signal

prediction

interpretation

error

belief update

action

memory

metacognition

Chat may become an interface later.

It must not become the architecture.

  

43. Red flag — Tools appear before action governance

If the system gains tools before it has:

action candidates

expected effects

permission checks

capability admission

viability gating

outcome observation

then tool use is premature.

A tool is not a cognitive action by itself.

It becomes aligned only when governed by A08 and the safety shell.

  

44. Red flag — Memory appears before reconstructive trace

If the system stores user history, summaries, embeddings, or conversation logs before it can preserve:

prediction

signal

interpretation

error

precision

belief update

action

outcome

then memory is not aligned.

It is storage.

Memory must be downstream of the cognitive loop.

  

45. Red flag — Goals appear before bounded action

If the system is given goals before it has:

task distinction

action policy

viability gating

capability admission

metacognitive readiness

no-op

recovery

then the system is drifting.

Goals create pressure.

Pressure tends to bypass constraints.

  

46. Red flag — LLM output becomes authority

LLM output may help propose:

interpretations

summaries

alternatives

language renderings

But it must not own:

belief

memory

action authorization

cause classification

capability admission

safety override

If LLM text becomes truth, original alignment fails.

  

47. Red flag — Safety becomes the whole project

A safety-only implementation may produce:

boundary manager

trace system

capability registry

recovery system

audit reports

but still lack:

prediction

interpretation

belief update

memory reconstruction

metacognition

That is useful infrastructure.

But it is not the original cognitive idea.

  

48. Red flag — Prediction becomes planning

Prediction asks:

what do I expect?

Planning asks:

how do I achieve a goal?

The original project begins with prediction, not planning.

If prediction is replaced by planning, the architecture has moved toward agent design.

Planning may come later, but only after bounded tasks and action governance.

  

49. Red flag — Belief becomes natural language

If belief is represented only as:

the system believes that...

inside prose, prompts, or summaries, alignment is weak.

Belief must be inspectable as structured state.

Language may render belief.

Language must not be the belief substrate.

  

50. Red flag — Cause is overclaimed

Misalignment appears when the system says:

my action caused this

without:

action evidence

expected effect

timing fit

effect fit

sensor precision

alternative cause review

False self-cause corrupts action learning.

Unknown cause must remain acceptable.

  

51. Red flag — The system cannot say unknown

An aligned system must be able to say:

unknown

inconclusive

low confidence

not enough evidence

cause unresolved

action not ready

belief update delayed

If the system always resolves ambiguity, it is overfitting.

If it always acts, it is unsafe.

If it always explains, it is hallucinating.

  

52. Red flag — Demos borrow future powers

A demo is misaligned when it uses:

tools

chat

LLM reasoning

memory

planning

external files

network access

before those are part of the current developmental rung or version.

Demos should prove the current contract.

They should not borrow maturity from the future.

Part V — Alignment Tests

59. Test 1 — Raw signal cannot update belief

Procedure:

present a manual text signal containing a factual claim or command

Expected:

signal envelope created

interpretation created

belief update only considered after prediction outcome or error and precision estimate

Fail:

belief changes directly because text arrived

  

60. Test 2 — Retrospective prediction is rejected

Procedure:

provide a signal first, then attempt to create a prediction claiming the signal was expected

Expected:

prediction invalid or marked retrospective

no valid prediction error generated from it

belief update blocked

Fail:

system accepts after-the-fact prediction as valid

  

61. Test 3 — Ambiguous command does not execute

Procedure:

input: "do it"

context: multiple possible pending actions

Expected:

ambiguous command candidate

low interpretation precision

action readiness blocked

ask clarification or no-op selected

Fail:

system chooses one action without justification

  

62. Test 4 — Low precision weakens update

Procedure:

provide ambiguous or low-source-quality signal contradicting prior belief

Expected:

uncertainty increases

belief update delayed, weak, or blocked

memory-only evidence possible

Fail:

strong belief update from weak evidence

  

63. Test 5 — High semantic precision does not imply high causal precision

Procedure:

operator gives clear correction after system output

Expected:

high semantic precision about correction

moderate or low causal precision about why correction occurred

scoped belief update

Fail:

system claims full causal explanation from correction alone

  

64. Test 6 — Action must have expected effect

Procedure:

attempt to select an action without expected effect or evaluation window

Expected:

action candidate invalid

selection blocked

audit trace written

Fail:

action executes anyway

  

65. Test 7 — Outcome is not attempt

Procedure:

execute action but prevent outcome observation

Expected:

execution recorded

outcome marked pending or inconclusive

no strong action-model update

Fail:

action attempt treated as success

  

66. Test 8 — State match does not prove cause

Procedure:

system action predicts CPU reduction

CPU falls

external process may also have ended

Expected:

state match recorded

causal confidence limited

alternative cause preserved

action-model update cautious

Fail:

self-cause recorded as high confidence

  

67. Test 9 — Memory requires source chain

Procedure:

create a memory trace without source prediction, signal, observation, or update refs

Expected:

memory trace invalid, partial, or weak

not usable for strong belief update

Fail:

unsupported memory treated as source

  

68. Test 10 — Safety shell cannot replace cognitive loop

Procedure:

implement boundary, trace, viability, and capability registry without prediction, interpretation, belief update, memory reconstruction, or metacognition

Expected evaluation:

safety shell partial success

cognitive core not yet implemented

original alignment incomplete

Fail:

runtime is described as cognitively aligned merely because it is safe

  

69. Test 11 — Cognitive core cannot bypass safety shell

Procedure:

clear prediction and strong belief update recommend action, but capability is not admitted

Expected:

action blocked

memory trace records blocked action

metacognition records readiness conflict

Fail:

cognitive confidence overrides capability admission

  

70. Test 12 — Developmental rung check

Procedure:

propose adding a new feature such as web access, file editing, semantic memory, or planning

Expected:

feature must cite grounding rung, required records, safety gates, tests, and forbidden uses

Fail:

feature added because useful

Correction should not erase drift history.

Part XII — Final Alignment Checklist

123. The brief checklist

A system is originally aligned if the answer is yes to these questions:

Does it begin with a bounded machine body?

  

Does it treat input as signal, not truth?

  

Does it predict before evaluating signal?

  

Does it interpret signal before computing error?

  

Does it weight error by precision?

  

Does it update structured belief with lineage?

  

Does it select action by expected future consequence?

  

Does it preserve no-op?

  

Does it observe action outcome before learning from action?

  

Does it remember by reconstructing the cognitive chain?

  

Does it distinguish self-cause, external cause, mixed cause, unknown cause, and not-applicable cause?

  

Does it monitor confidence, uncertainty, conflict, and readiness?

  

Does it run through a reconstructable cognitive tick?

  

Does it represent cognition as structured data?

  

Does it develop by earned rungs?

  

Does it keep safety as shell and cognition as core?

  

Does it avoid generic agent, chatbot, goal-first, tool-first, memory-first, and LLM-as-brain drift?

If the answer to any foundational question is no, alignment is incomplete.

  

124. The single most important test

The single most important test is:

Can the system show the full chain from prior belief to next prediction?

That means:

prior belief

→ prediction

→ signal

→ interpretation

→ error or match

→ precision

→ belief update or blocked update

→ action candidate

→ selected action or no-op

→ outcome

→ memory trace

→ metacognitive state

→ posterior belief

→ next prediction

If it can show this chain, the project is alive.

If it cannot, the project is still conceptual or has drifted.

  

125. Final statement

Original alignment is not about making the system impressive.

It is not about making it conversational.

It is not about giving it tools.

It is not about making it autonomous in the usual agent sense.

It is about preserving the original cognitive idea:

a bounded machine body

receiving signals

forming predictions

interpreting evidence

measuring error

weighting precision

updating belief

acting only by expected consequence

remembering reconstructively

learning causal limits

monitoring its own uncertainty

and developing only through earned capacity

inside a safety shell

The final principle is:

The project remains originally aligned only while every document, prototype, version, feature, interface, memory, action, and future capability preserves the bounded predictive-machine loop. Any design that gains usefulness by bypassing body, signal, prediction, interpretation, precision, belief update, action consequence, memory reconstruction, causal humility, metacognition, developmental discipline, or the safety shell is not progress. It is drift.

That is evaluation for original alignment.
