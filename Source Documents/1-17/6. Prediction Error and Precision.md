# **A06 -- Prediction Error and Precision**

**Project status:** cognitive-core canon  
**Purpose:** define how the system measures mismatch between prediction and interpreted observation, and how precision determines whether that mismatch should update belief.  
**Rule:** prediction error is not generic surprise. It is structured, typed, target-specific mismatch. Error must be weighted by precision before it can influence belief update, action selection, or memory reconstruction.
* * *

## **1. Why this document exists**

The system cannot learn merely because signals arrive.

It learns when a prediction meets an interpreted observation and the difference is meaningful enough to update the model.

That difference is prediction error.

But prediction error must be handled carefully.

If the system treats every mismatch as equally important, it will overlearn from noise.

If it ignores high-quality mismatch, it will fail to adapt.

If it computes error against raw signal instead of interpreted observation, it will confuse data with meaning.

If it updates belief without precision, it will become unstable.

This document defines the system's learning interface:
    
    
    prediction
    → interpreted observation
    → prediction error
    → precision weighting
    → belief update candidate

* * *

## **2. Core thesis**

The core thesis is:

Prediction error is the structured mismatch between what the system expected and what it interpreted. Precision determines how much that mismatch should matter.

In simpler form:
    
    
    prediction error = what was wrong
    precision = how much to trust the evidence
    weighted error = how strongly the model should consider changing

The system should not ask only:
    
    
    Was I wrong?

It should ask:
    
    
    What kind of wrong was I?
    How strong was the mismatch?
    How reliable was the observation?
    Which model does this affect?
    How much should belief change?
    What uncertainty remains?

* * *

## **3. Short definition**

A **prediction error** is:
    
    
    a structured difference between a prediction and an interpreted observation.

A **precision estimate** is:
    
    
    an estimate of how reliable the interpreted observation is for a specific belief target.

A **weighted prediction error** is:
    
    
    prediction error adjusted by precision, relevance, freshness, admissibility, and update eligibility.

A **belief update candidate** is:
    
    
    a proposed model change generated from weighted prediction error.

* * *

## **4. Prediction error is not surprise**

Surprise is vague.

Prediction error is structured.

The system should not merely record:
    
    
    unexpected thing happened

It should record:
    
    
    prediction expected trace write success
    interpreted observation reported trace write failure
    mismatch type: body/action outcome error
    evidence precision: high for trace-store state, low for cause
    affected models: trace model, viability model, action model
    recommended update: lower trace-store reliability under current condition

Prediction error should be inspectable.

If the error cannot be explained structurally, it should not strongly update belief.

* * *

## **5. Prediction error is not emotion**

Prediction error is not fear, frustration, disappointment, or confusion in a human sense.

Avoid:
    
    
    the system was surprised
    the system felt wrong
    the system became worried
    the system wanted to correct itself

Prefer:
    
    
    prediction mismatch occurred
    semantic error was detected
    causal uncertainty increased
    weighted error exceeded update threshold
    belief update was proposed

Prediction error is operational.

It is not psychological.

* * *

## **6. Prediction error requires prior prediction**

A system cannot honestly compute prediction error unless the prediction existed before the observation.

Correct sequence:
    
    
    prediction recorded
    signal arrives
    signal interpreted
    prediction compared with interpreted observation
    error computed

Incorrect sequence:
    
    
    signal arrives
    system invents what it would have predicted
    system claims prediction error

Retrospective explanation is not prediction.

The prediction must be traceable before evaluation.

* * *

## **7. Prediction error compares interpretation, not raw signal**

Prediction error should compare prediction to interpreted observation.

Correct:
    
    
    prediction:
    operator likely wants next A-series document
    
    signal:
    "A06 -- Prediction Error and Precision"
    
    interpretation:
    operator requests next A-series document
    
    error:
    prediction matched

Incorrect:
    
    
    prediction compared directly to raw text tokens

Raw signal may be ambiguous.

Interpretation gives the signal meaning.

Prediction error belongs after interpretation.

* * *

## **8. Prediction error is typed**

Prediction error should have a type.

Possible error types:
    
    
    sensory_error
    semantic_error
    timing_error
    magnitude_error
    causal_error
    self_model_error
    sensor_model_error
    operator_model_error
    task_model_error
    project_model_error
    action_outcome_error
    memory_error
    viability_error
    privacy_error
    capability_error

Type matters because different errors update different model components.

A semantic error should not update the CPU model.

A trace failure should not update operator intent.

A memory contradiction should not directly authorize action.

* * *

## **9. Sensory error**

A **sensory error** occurs when expected sensor output differs from interpreted sensor output.

Examples:
    
    
    expected memory sensor to respond
    observed memory sensor unavailable
    
    expected trace-store sensor to report writable
    observed permission denied
    
    expected body sensor sample within normal interval
    observed stale sample

Possible belief targets:
    
    
    sensor_model
    body_model
    viability_model
    uncertainty_model

Sensory error often affects confidence in the sensorium.

* * *

## **10. Semantic error**

A **semantic error** occurs when expected meaning differs from interpreted meaning.

Example:
    
    
    prediction:
    operator wants continuation of safety canon
    
    interpreted observation:
    operator wants return to original cognitive-core idea
    
    error:
    semantic/project-model error

Possible belief targets:
    
    
    operator_model
    task_model
    project_model
    memory_model
    uncertainty_model

Semantic error is especially important for human input and language signals.

* * *

## **11. Timing error**

A **timing error** occurs when an expected event happens too early, too late, or outside its evaluation window.

Examples:
    
    
    expected trace write within current tick
    observed trace write after delay
    
    expected operator clarification in next message
    no clarification arrives within window
    
    expected action outcome within five ticks
    outcome appears after ten ticks

Timing error may update:
    
    
    sensor_latency_model
    action_model
    prediction_window_model
    uncertainty_model

Timing error should not automatically mean the prediction was wrong in content.

It may mean the timing model was wrong.

* * *

## **12. Magnitude error**

A **magnitude error** occurs when the direction is correct but the size differs.

Example:
    
    
    prediction:
    memory pressure will rise slightly
    
    observation:
    memory pressure rises sharply

Another example:
    
    
    prediction:
    reducing polling will slightly reduce CPU
    
    observation:
    CPU drops significantly

Magnitude error may update:
    
    
    resource_model
    action_consequence_model
    body_model
    prediction_confidence_model

Magnitude matters because weak matches can hide strong model errors.

* * *

## **13. Causal error**

A **causal error** occurs when the observed state matches but the cause differs from expectation.

Example:
    
    
    prediction:
    CPU will fall because polling was reduced
    
    observation:
    CPU falls, but evidence suggests external process ended
    
    outcome:
    state match, causal mismatch

Causal error is important because state match alone can strengthen the wrong belief.

The system must distinguish:
    
    
    what happened

from:
    
    
    why it happened

* * *

## **14. Self-model error**

A **self-model error** occurs when the system's expectation about its own action, effect, or boundary is wrong.

Examples:
    
    
    system expected its action to write trace
    no trace appeared
    
    system expected it had permission
    permission denied
    
    system expected action would affect body state
    no effect observed

Possible belief targets:
    
    
    self_model
    action_model
    permission_model
    body_model
    cause_model

Self-model error is central to machine self-understanding.

* * *

## **15. Sensor-model error**

A **sensor-model error** occurs when a sensor behaves differently from its model.

Examples:
    
    
    sensor expected high precision
    later evidence shows signal was misleading
    
    sensor expected low latency
    signal arrives late
    
    sensor expected stable output
    signal fluctuates strongly

Possible belief targets:
    
    
    sensor_model
    precision_model
    uncertainty_model
    interpretation_model

Sensor-model error helps the system learn how much to trust each sensor.

* * *

## **16. Operator-model error**

An **operator-model error** occurs when the system's expectation about operator intent, preference, correction, or next signal is wrong.

Example:
    
    
    prediction:
    operator wants a brief outline
    
    interpreted observation:
    operator wants full document generation

Possible belief targets:
    
    
    operator_model
    task_model
    project_model
    interpretation_model

Operator-model error should be updated carefully.

One operator correction may be high precision for the current context but not necessarily for all future contexts.

* * *

## **17. Task-model error**

A **task-model error** occurs when the system misunderstands the structure of the current work.

Example:
    
    
    prediction:
    current task is to continue the old safety canon
    
    interpreted observation:
    current task is to build the A-series cognitive core canon

Possible belief targets:
    
    
    task_model
    project_model
    operator_model
    memory_model

Task-model error often requires reframing action.

* * *

## **18. Project-model error**

A **project-model error** occurs when the system's understanding of the project's conceptual direction is wrong.

Example:
    
    
    prediction:
    the project centre is governed runtime safety
    
    interpreted observation:
    the project centre is predictive machine cognition, with safety as shell

Possible belief targets:
    
    
    project_model
    conceptual_lineage_model
    document_sequence_model
    memory_model

Project-model error can justify strong belief update when supported by high-precision operator correction.

* * *

## **19. Action-outcome error**

An **action-outcome error** occurs when an action produces a different result than predicted.

Examples:
    
    
    action:
    ask clarification
    
    prediction:
    operator will clarify ambiguity
    
    observation:
    operator gives unrelated instruction

Another:
    
    
    action:
    reduce polling
    
    prediction:
    CPU decreases
    
    observation:
    CPU unchanged

Possible belief targets:
    
    
    action_model
    operator_model
    body_model
    cause_model
    uncertainty_model

Action-outcome error is how the system learns action consequences.

* * *

## **20. Memory error**

A **memory error** occurs when reconstructed memory conflicts with current evidence or later correction.

Examples:
    
    
    memory reconstruction:
    operator accepted prior outline
    
    new signal:
    operator says prior outline distorted original idea

Memory error may update:
    
    
    memory_model
    project_model
    operator_model
    uncertainty_model

Memory error should not erase the original memory trace.

It should revise the reconstruction and preserve the contradiction.

* * *

## **21. Viability error**

A **viability error** occurs when predicted operational condition differs from observed condition.

Examples:
    
    
    prediction:
    viability remains safe
    
    observation:
    trace store failure makes viability critical

or:
    
    
    prediction:
    low-cost mode will reduce pressure
    
    observation:
    pressure remains high

Possible belief targets:
    
    
    viability_model
    body_model
    action_model
    resource_model

Viability error should often affect action scope.

* * *

## **22. Privacy error**

A **privacy error** occurs when a signal, interpretation, memory, or action violates expected privacy handling.

Examples:
    
    
    prediction:
    signal is internal runtime only
    
    observation:
    signal contains operator-private content
    
    prediction:
    raw signal may be stored
    
    observation:
    privacy class forbids raw storage

Possible belief targets:
    
    
    privacy_model
    sensor_model
    memory_model
    action_model
    safety_model

Privacy error should reduce admissibility and may block belief update or memory storage.

* * *

## **23. Capability error**

A **capability error** occurs when expected capability availability differs from actual availability.

Examples:
    
    
    prediction:
    trace write capability is enabled
    
    observation:
    capability disabled or permission denied

or:
    
    
    prediction:
    action can be performed
    
    observation:
    action not admitted

Possible belief targets:
    
    
    capability_model
    permission_model
    action_model
    viability_model

Capability error should not create capability.

It should update the model of what is available.

* * *

## **24. Error magnitude**

Error magnitude measures how large the mismatch is.

Magnitude may be:
    
    
    none
    low
    moderate
    high
    critical

or numeric if implementation supports it.

Magnitude should consider:
    
    
    distance between expected and observed state
    semantic difference
    timing difference
    resource difference
    confidence of prediction
    severity of consequence
    scope of affected model

Magnitude alone is not enough.

A large mismatch with low precision may produce weak update.

A smaller mismatch with high precision may produce strong update.

* * *

## **25. Precision**

Precision estimates how reliable the interpreted observation is for the target model.

Precision is not general trust.

Precision is target-specific.

Example:
    
    
    trace write failure:
    high precision for trace-store state
    medium precision for viability
    low precision for root cause

Another:
    
    
    operator correction:
    high precision for current operator dissatisfaction
    high precision for requested conceptual direction
    lower precision for implementation details not explicitly stated

The system should avoid a single global trust score.

* * *

## **26. Precision dimensions**

Useful precision dimensions include:
    
    
    sensory_precision
    temporal_precision
    semantic_precision
    causal_precision
    self_cause_precision
    external_cause_precision
    action_outcome_precision
    memory_precision
    viability_precision
    privacy_precision

Each dimension may affect different belief targets.

Example:
    
    
    {
      "semantic_precision": 0.94,
      "causal_precision": 0.52,
      "temporal_precision": 0.98
    }

This means:
    
    
    strong update may be justified for meaning
    weaker update for cause
    very strong confidence about timing

* * *

## **27. Precision is not confidence**

Confidence and precision are related but not identical.

**Confidence** estimates how likely the interpretation is.

**Precision** estimates how reliable the observation is for updating a specific belief target.

Example:
    
    
    interpretation confidence:
    operator is requesting A06 document -- high
    
    precision:
    high for task_model
    high for operator_model
    medium for long-term preference model
    low for system implementation priority

A confident interpretation may still have limited precision for some targets.

* * *

## **28. Precision is not importance**

A signal can be important but low precision.

Example:
    
    
    critical sensor emits malformed warning

Importance:
    
    
    high

Precision:
    
    
    low until validated

The system should treat it as urgent but uncertain.

High importance may trigger safe observation or restriction.

It should not automatically trigger strong belief update.

* * *

## **29. Precision sources**

Precision may depend on:
    
    
    sensor model
    signal freshness
    signal clarity
    schema validity
    source reliability
    context strength
    interpretation confidence
    alternative interpretations
    historical calibration
    privacy constraints
    contradictory evidence

Precision should be computed or estimated explicitly.

If precision is unknown, the system should not assume it is high.

* * *

## **30. Precision and freshness**

Freshness affects precision.

Example:
    
    
    current body signal
    → higher temporal precision
    
    stale body signal
    → lower temporal precision
    
    old operator correction
    → may retain conceptual relevance but lose current-intent precision

Freshness does not equal truth.

It only affects how strongly the signal should apply to current belief.

* * *

## **31. Precision and source reliability**

Source reliability affects precision.

Example:
    
    
    sensor with repeated failures
    → lower precision
    
    operator correction to current output
    → high semantic precision
    
    LLM proposal without validation
    → low-to-moderate precision
    
    memory reconstruction from incomplete traces
    → reduced memory precision

Reliability should be learned over time.

But early defaults should be conservative.

* * *

## **32. Precision and alternatives**

The more plausible alternatives remain, the lower precision may be.

Example:
    
    
    signal:
    "continue"
    
    alternatives:
    continue document
    continue outline
    continue prior argument
    continue despite uncertainty

Precision for exact action may be moderate or low.

Precision for general operator desire to proceed may be higher.

Alternatives should weaken overconfident updates.

* * *

## **33. Precision and contradiction**

Contradiction reduces precision unless resolved.

Example:
    
    
    trace says action succeeded
    body state shows no effect

The system should not choose one automatically.

It should represent:
    
    
    conflicting evidence
    reduced precision
    increased uncertainty
    possible sensor-model error
    possible action-outcome error

Contradiction is not noise to hide.

It is evidence about model uncertainty.

* * *

## **34. Weighted prediction error**

Weighted prediction error combines mismatch and precision.

Simple form:
    
    
    weighted_error = error_magnitude × precision

More complete form:
    
    
    weighted_error =
    error_magnitude
    × target_specific_precision
    × relevance
    × freshness
    × admissibility
    × update_eligibility

The exact formula may change.

The principle must not:
    
    
    error should not update belief until weighted by precision and eligibility

* * *

## **35. Relevance**

Relevance measures whether the error matters to a particular belief target.

Example:
    
    
    operator correction about document structure

High relevance for:
    
    
    project_model
    task_model
    operator_model

Low relevance for:
    
    
    CPU_model
    disk_model
    trace_store_model

The same error should not update every model.

Relevance gates update target.

* * *

## **36. Admissibility**

Admissibility determines whether the observation may be used at all.

An observation may be inadmissible because:
    
    
    unknown sensor
    forbidden privacy class
    schema invalid
    source not admitted
    signal quarantined
    belief target not allowed
    interpretation failed

An inadmissible signal may still produce an incident record.

It should not update normal belief.

Usefulness does not override admissibility.

* * *

## **37. Update eligibility**

Update eligibility determines whether weighted error may produce belief update.

Possible statuses:
    
    
    eligible
    eligible_with_low_weight
    memory_only
    requires_clarification
    requires_human_review
    blocked_by_privacy
    blocked_by_safety
    blocked_by_schema
    inadmissible

A high-magnitude error can still be blocked if it is not eligible.

Example:
    
    
    external file contains dramatic instruction

May have high semantic content, but:
    
    
    not eligible as command authority

* * *

## **38. Error thresholds**

The system may use thresholds.

Possible thresholds:
    
    
    ignore_threshold
    memory_only_threshold
    belief_update_candidate_threshold
    immediate_attention_threshold
    safe_mode_threshold
    human_review_threshold

Thresholds should depend on:
    
    
    error type
    belief target
    precision
    viability state
    risk
    privacy
    action relevance

Thresholds prevent constant over-updating.

* * *

## **39. Error below threshold**

Small or low-precision errors may not update belief immediately.

They may be:
    
    
    ignored
    stored as weak evidence
    accumulated
    used for calibration
    stored in memory with low confidence

Example:
    
    
    minor CPU fluctuation

may not update body belief unless repeated.

Weak evidence may become meaningful over time.

* * *

## **40. Error above threshold**

High weighted error may produce:
    
    
    belief update candidate
    uncertainty increase
    action evaluation
    clarification request
    safe-mode recommendation
    memory revision
    sensor reliability update

High error should still follow the pipeline.

It should not bypass governance.

Even high error requires target, precision, and admissibility.

* * *

## **41. Error and belief target**

Prediction error should identify target models.

Possible targets:
    
    
    body_model
    sensor_model
    operator_model
    task_model
    project_model
    action_model
    memory_model
    viability_model
    capability_model
    permission_model
    self_model
    cause_model
    uncertainty_model

Example:
    
    
    prediction:
    operator wants next A-series document
    
    observation:
    operator asks for unrelated implementation code
    
    error targets:
    operator_model
    task_model
    project_model

Targeting prevents global model distortion.

* * *

## **42. Error and belief update candidate**

A weighted prediction error may produce a belief update candidate.

A belief update candidate should include:
    
    
    candidate_id
    source_error_id
    target_model
    prior_belief_ref
    proposed_change
    update_strength
    evidence_precision
    remaining_uncertainty
    alternative_updates
    recommended_status

A candidate is not yet the final update.

It is a structured proposal for A07.

* * *

## **43. Belief update candidate example**

Example:
    
    
    {
      "candidate_id": "buc_0006",
      "source_error_id": "err_0006",
      "target_model": "project_model",
      "prior_belief_ref": "belief_project_0005",
      "proposed_change": "increase confidence that cognitive-core canon is primary and safety canon is containment shell",
      "update_strength": 0.82,
      "evidence_precision": {
        "semantic": 0.95,
        "temporal": 0.99,
        "causal": 0.65
      },
      "remaining_uncertainty": [
        "exact implementation integration remains unresolved"
      ],
      "alternative_updates": [
        "treat as local document preference only",
        "discard safety canon entirely"
      ],
      "recommended_status": "apply_after_validation"
    }

This is how error becomes structured adaptation.

* * *

## **44. Error and uncertainty**

Prediction error may increase or decrease uncertainty.

It may decrease uncertainty when:
    
    
    high-precision observation confirms prediction
    clear correction resolves ambiguity
    action outcome matches expected effect

It may increase uncertainty when:
    
    
    prediction mismatches
    signals contradict
    cause is unknown
    precision is low
    interpretation alternatives remain

The system should not treat every error as clarity.

Some errors reveal ignorance.

* * *

## **45. Error and action**

Prediction error can inform action, but it should not directly cause action.

Correct path:
    
    
    prediction error
    → weighted error
    → belief update candidate
    → action evaluation
    → safety and viability check
    → selected action

Incorrect path:
    
    
    prediction error
    → immediate action

Examples:
    
    
    semantic error
    → maybe ask clarification
    
    trace error
    → maybe enter safe mode
    
    memory error
    → maybe mark reconstruction uncertain

But each action still requires policy evaluation.

* * *

## **46. Error and memory**

Memory should store prediction error.

A memory trace should preserve:
    
    
    prediction
    interpreted observation
    error type
    error magnitude
    precision
    weighted error
    belief update candidate
    actual belief update if applied
    action outcome
    remaining uncertainty

Without error, memory becomes event history.

With error, memory records model change pressure.

This supports reconstructive memory.

* * *

## **47. Error and calibration**

Prediction errors should calibrate future predictions.

The system should learn:
    
    
    which predictions are overconfident
    which sensors are less precise than assumed
    which interpretations often require correction
    which action outcomes are unreliable
    which memory reconstructions are weak

Calibration requires storing:
    
    
    prediction confidence
    observed outcome
    precision estimate
    error magnitude
    final update
    later correction

Without calibration, confidence becomes decorative.

* * *

## **48. Error and repeated evidence**

One error may be weak.

Repeated error may become strong.

Example:
    
    
    trace write failure once
    → possible transient issue
    
    trace write failure repeatedly
    → trace-store reliability belief should update strongly

The system should distinguish:
    
    
    single event
    recurring pattern
    contradictory pattern
    decaying pattern

Repeated errors should update cautiously but meaningfully.

* * *

## **49. Error and overfitting**

The system should avoid overfitting to one signal.

Overfitting occurs when:
    
    
    single correction rewrites too broad a model
    one sensor failure destroys sensor trust
    one successful action creates overconfidence
    one mismatch invalidates an entire project model

Precision helps, but scope also matters.

A belief update should match the scope of the evidence.

* * *

## **50. Error and underfitting**

The system should also avoid underfitting.

Underfitting occurs when:
    
    
    repeated corrections are treated as isolated
    high-precision mismatch does not update belief
    action failures do not update action model
    sensor unreliability is ignored

The system should be willing to change when evidence justifies it.

Stability must not become rigidity.

* * *

## **51. Error and causal humility**

Prediction error does not automatically identify cause.

Example:
    
    
    prediction:
    memory stable
    
    observation:
    memory rose

This proves mismatch.

It does not prove cause.

Possible causes:
    
    
    own action
    external process
    sensor noise
    delayed effect
    unknown

Causal interpretation requires additional evidence.

The system must preserve causal humility.

* * *

## **52. Error and self-cause**

Self-cause precision should be separate.

A mismatch may be high precision for state but low precision for self-cause.

Example:
    
    
    memory pressure rose after action

High precision:
    
    
    memory pressure rose

Lower precision:
    
    
    my action caused it

The system should not over-attribute.

Self-model learning requires careful action-outcome evidence.

* * *

## **53. Error and missing evidence**

Missing evidence is not always mismatch.

Example:
    
    
    expected operator response
    no response yet

Could mean:
    
    
    operator absent
    message delayed
    prediction window too short
    interface failed
    no response needed

Missing evidence may produce:
    
    
    inconclusive outcome
    timing uncertainty
    sensor uncertainty
    weak mismatch

Absence should not automatically become strong error.

* * *

## **54. Error and malformed evidence**

Malformed evidence may indicate:
    
    
    sensor failure
    schema failure
    privacy problem
    corruption
    external attack
    unsupported modality

Malformed evidence should not update ordinary belief directly.

It may update:
    
    
    sensor_model
    trace_model
    viability_model
    uncertainty_model

or trigger quarantine.

Malformed evidence is evidence about the evidence channel.

* * *

## **55. Error and privacy**

A privacy-blocked signal may prevent error evaluation.

Example:
    
    
    prediction expected external content type
    signal arrives but privacy class forbids inspection

Outcome may be:
    
    
    inconclusive due to privacy block

The system should not bypass privacy to reduce error.

Privacy constraints may preserve uncertainty.

That is acceptable.

* * *

## **56. Error and safety**

High prediction error may affect safety state.

Examples:
    
    
    trace write failed
    → restrict learning
    
    boundary signal mismatched
    → enter safe mode
    
    action outcome unexpected
    → restrict repeated action
    
    sensor contradiction high
    → mark uncertainty and avoid risky action

Safety response should be proportional.

Error should not trigger unbounded repair.

* * *

A prediction error object may include:
    
    
    error_id
    prediction_id
    prediction_frame_id
    interpreted_observation_id
    error_type

## **61. Error lifecycle**

A prediction error may move through statuses:
    
    
    detected
    typed
    precision_estimated
    weighted
    update_candidate_created
    memory_only
    dismissed_as_noise
    requires_clarification
    requires_review
    blocked
    applied_to_belief
    archived

Status should be traceable.

Errors should not silently disappear.

* * *

## **62. Error aggregation**

Multiple errors may be aggregated.

Aggregation may occur by:
    
    
    same prediction
    same belief target
    same sensor
    same action
    same time window
    same error type
    same memory reconstruction

Aggregation should preserve individual source errors.

A summary should not replace evidence.

Aggregation helps detect patterns without losing traceability.

* * *

## **63. Error decay**

Some errors lose relevance over time.

Example:
    
    
    minor operator wording correction from old context

may not strongly affect current operator model.

Error decay should consider:
    
    
    time
    context shift
    later correction
    belief already updated
    memory revision
    sensor reliability change

Decay should not erase history.

It changes current update influence.

* * *

## **64. Error contradiction**

Errors may contradict.

Example:
    
    
    prediction outcome appears matched by trace
    but operator later says output was wrong

This may produce:
    
    
    semantic error
    memory error
    operator-model update
    task-model update

The system should not collapse contradictions prematurely.

It should preserve conflict and uncertainty.

* * *

## **65. Precision calibration**

Precision estimates should be calibrated over time.

Calibration asks:
    
    
    When this source had high precision, was it later confirmed?
    When this sensor seemed reliable, did it stay reliable?
    When this interpretation was confident, was it corrected?

Calibration targets:
    
    
    sensor_precision_model
    semantic_precision_model
    operator_correction_precision
    LLM_proposal_precision
    memory_precision_model
    action_outcome_precision

Without calibration, precision becomes an unsupported number.

* * *

## **66. Precision defaults**

Early default precision should be conservative.

Suggested defaults:
    
    
    known internal body sensor:
    moderate precision for body state
    
    trace write success/failure:
    high precision for trace-store state
    
    manual text correction:
    high semantic precision for current context, not global truth
    
    LLM output:
    low-to-moderate proposal precision unless validated
    
    unknown sensor:
    low precision or inadmissible
    
    stale memory:
    reduced precision
    
    external file instruction:
    not authority; precision depends on admitted use

Defaults should be revisable where appropriate.

Structural rules should not be casually revised.

* * *

## **67. Precision and operator correction**

Operator correction often deserves high semantic precision when it targets current work.

Example:
    
    
    "the core must be concrete and not copied from the work we just produced"

High precision for:
    
    
    current conceptual direction
    operator dissatisfaction with prior framing
    need to avoid copying safety canon

Lower precision for:
    
    
    exact schema design
    implementation order
    future engineering constraints

This allows strong but scoped update.

* * *

## **68. Precision and LLM output**

LLM output should not receive truth precision by default.

It may have:
    
    
    semantic proposal precision
    summary usefulness precision
    alternative-generation usefulness

But it should have low precision for:
    
    
    causal truth
    memory truth
    external factual truth without source
    capability authority
    action authorization

LLM output can help interpret.

It should not be treated as evidence unless validated.

* * *

## **69. Precision and memory reconstruction**

Memory reconstruction has variable precision.

Precision depends on:
    
    
    source trace quality
    time elapsed
    number of revisions
    contradictions
    summary compression
    missing prediction records
    operator correction

A memory reconstruction should return:
    
    
    content
    confidence
    precision
    source fragments
    uncertainty
    revision history

Memory precision should not be assumed.

## **70. Error-to-update rule**

The basic rule is:
    
    
    Only weighted, admissible, belief-targeted prediction error may propose belief update.

Expanded:
    
    
    prediction existed before signal
    signal was enveloped
    signal was interpreted
    error was typed
    precision was estimated
    admissibility was checked
    target model was identified
    weighted error exceeded threshold
    uncertainty was preserved

Only then may A07 perform belief update.

* * *

## **71. Error-to-action rule**

The basic rule is:
    
    
    Prediction error may inform action evaluation but may not directly authorize action.

Examples:
    
    
    semantic error
    → may recommend clarification
    
    trace error
    → may recommend safe mode
    
    action-outcome error
    → may recommend retry restriction
    
    memory error
    → may recommend reconstruction revision

But action still requires:
    
    
    policy evaluation
    cost evaluation
    risk evaluation
    viability check
    capability check
    safety shell

* * *

## **72. Error-to-memory rule**

The basic rule is:
    
    
    Prediction error should be preserved in memory as part of the model-change chain.

Memory should store:
    
    
    what was predicted
    what was interpreted
    what error occurred
    how precise the evidence was
    what update was proposed
    whether update was applied
    what uncertainty remained

This makes memory reconstructive.

* * *

## **73. Error-to-uncertainty rule**

The basic rule is:
    
    
    Prediction error should update uncertainty even when it does not update belief.

Example:
    
    
    low precision mismatch

may not change belief, but should increase uncertainty.

Example:
    
    
    high precision match

may reduce uncertainty.

Uncertainty is a first-class output.

## **77. Incorrect assumptions about error**

Avoid these assumptions:

    any match means the model is right
    missing evidence means mismatch
    prediction error identifies cause

    error should immediately trigger action

Correct assumptions:

    match may still hide causal error

    cause requires separate evidence
    precision controls update strength
    confidence and precision differ
    LLM output is a proposal
    operator correction is scoped
    action requires policy evaluation

## **79. Evaluation questions**

Prediction error and precision should be evaluated by asking:
    
    
    Did the prediction exist before the signal?
    Was the signal interpreted before error was computed?
    Is the error typed?
    Is the error magnitude represented?
    Is precision target-specific?
    Are confidence and precision distinguished?
    Is admissibility checked?
    Is update eligibility explicit?
    Is the affected belief target identified?
    Can missing evidence become inconclusive?
    Can causal mismatch be represented?
    Can low precision block strong update?
    Can high precision correction produce scoped update?
    Can error inform action without authorizing it?
    Can memory preserve the error and update chain?

If not, the system is not yet learning in the intended sense.

## **86. Final statement**

Prediction error is the hinge between expectation and learning.

It is not surprise.

It is not emotion.

It is not proof.

It is structured mismatch between prediction and interpreted observation.

Precision determines how strongly that mismatch should matter.

The final principle is:

Belief may only be pressured to change by admissible, typed, target-specific prediction error weighted by precision, relevance, freshness, and update eligibility. Error without precision is noise; precision without error is inert; together they form the learning signal.

That is prediction error and precision.
